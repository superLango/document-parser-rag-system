## 4. 关键结论

### v2 全链路的覆盖率上限 ≈ 70%
- 已覆盖全部 20 份中最有潜力的 12 份；
- 剩余大缺口文档（gbt-5231、gbt-3077）全链路反而下降；
- 强制全链路最多只能让个别文档 +20 左右，无法达到 G1（覆盖率 72%，需 +206 匹配）。

### 根因
- v2 绑定在化学宽表/英文标准/条款内容上系统性不足；
- 全链路只是"更完整地跑 v2"，不能解决 v2 的模型/表结构缺陷；
- 后处理+全链路组合已到 ~69.9% 天花板。

## 5. 决策：按用户授权，切换 app_v3 原生重做

**停止继续调 v2 全链路/路由。**  
S16 起使用 app_v3 自己的抽取架构（不依赖 v2 绑定）：

1. **WP1.3 程序化表格**：TableIR + 模型生成 DSL（melt/explode/pivot）→ 执行 → 回放校验；
2. **WP1.5 条款通道**：正文/条款抽取（高倍/弯曲/热处理），带引文证据；
3. **WP1.4 双通道**：程序化通道 + LLM 语义通道，冲突升级；
4. **验证/仲裁**：证据、值守恒、条件完整性、未解决队列；
5. **目标**：先 3–5 份文档达到 G1（覆盖率≥72%、一致率≥0.80、多余<2000），再扩到 20 份。
