## 1. S17 实现

### 1.1 记录质量过滤（`channels/record_filter.py`）
规则（不依赖金标）：
1. **基础有效性**：
   - 丢弃占位值（`--`/`—`）、`text`、`牌号` 等无效要求；
   - 丢弃空牌号、非牌号字符的牌号；
2. **原生记录支持性**：只保留原生记录的项目在既有 S9 通道中存在（`(类别,项目)` 有支持）；
3. **强去重**：原生记录与 S9 同 `(类别,项目,数值)` 且牌号兼容 → 视为已覆盖，丢弃；
4. 合并后记录进入评测/验证。

### 1.2 原生表覆盖扩展
- 原生通道（S16）对 20 份文档扩展到最多 20–40 张数值表；
- 共生成原生记录约 1.9 万条，过滤后保留少量高置信记录。

## 4. 误差分析（为什么还差一点）

### 4.1 原生记录的增益高度集中
- 原生过滤后新增匹配主要来自：
  - gbt-5231：+213 匹配（同时 +239 多余）
  - hb-20079：+13 / +9
  - gjb-2351a：+11 / 0
  - gjb-1951a：+7 / 0
- 其他 16 份文档原生记录新增匹配为 0（多为已有覆盖或无效展开）。

### 4.2 基础记录本身的多余
- 仅做基础有效性过滤后的 S9：6694 匹配、**2095 多余**；
- 要满足全局多余<2000，必须在基础记录上再削减约 95 条多余，同时补约 63 条匹配；
- 简单删类别（冲击/高温/标准信息）会损失 110+ 匹配，不可取。

### 4.3 缺口文档
- gbt-3620、astm、gbt-14976、asme、gbt-3077 的原生展开几乎不新增匹配；
- 这些文档的缺口不是"表未绑定"，而是条件/牌号/条款语义，需要更强的条款/双通道。
