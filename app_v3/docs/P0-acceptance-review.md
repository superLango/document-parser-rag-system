## 4. 为什么按 P0 方案走仍未达标（根因）

### R1 P0 目标与 P0 手段不匹配
P0 的交付物是：
- 规范 Schema、归一化、验证器、评测基线；
- 对象是 **v2 已经抽出来的记录**。

但缺失记录中大部分是 **v2 根本没绑定的列/表/条款**：
- 化学 ~1886、室温 ~625、高倍 149、硬度 144、热处理 132、冲击 88……

归一化/验证器无法生成"从没抽出来的记录"，所以覆盖率上限被锁死。

### R2 验证器只能发现问题，不能修复抽取
S2–S5 把 unresolved 从 1544 降到 820，但匹配数只从 6672 → 6760（+88）。  
验证器提升"质量可见性"，不提升覆盖率。

### R3 条件/列错配不是归一化能解决的
- 室温拉伸匹配后值一致约 50%；
- 冲击曾低至 3.6%；
- 这是"列条件错配/绑定错位"，需要重新绑定或程序化表格变换，P0 无此能力。

### R4 英文标准/牌号体系超出 P0 范围
- AMS/ISO 长期 0% 匹配；
- UNS/Grade ↔ 常用牌号不是单纯文本归一化能覆盖的。

### R5 目标未做可行性校准
P0 的 0.90/70% 是"愿望值"，不是从基线 68.61%/0.7899 推导的可达值；  
S1–S10 十轮后实际只提升：
- 匹配 +88（+1.3%）
- 覆盖率 +0.91pp
- 一致率 +0.18pp

### R6 阶段门禁未执行
方案写了"P0 未达标不进入 P1"，实际未执行；发现后处理收益趋近 0 时（S10）才转向。

## 5. 经验教训

1. **验收标准必须"手段可达"**：P0 只做归一化/验证，就不能承诺 90% 一致率；
2. **缺失来源必须分层统计**：未绑定/绑定错/条件错/条款缺失/OCR 缺失；
3. **后处理收益要早停**：连续 2 轮无显著提升即停止；
4. **阶段门禁硬约束**：未过门禁不得进入下一阶段；
5. **少量文档试点**：先 3–5 份高潜力文档验证，不跑全量。
