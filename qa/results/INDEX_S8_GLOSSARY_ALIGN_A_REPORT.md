## 已实现的对齐项

| 差距 | 实现 |
|------|------|
| G1 API 参数面板 | 新建向导支持路径/Query/Header 参数动态增删（启用开关）、POST JSON body、超时配置；后端 source_api 支持 path 替换/header 合并/body JSON/超时覆盖 |
| G3 批量保存端点 | `PUT /kb/{kb_id}/term-bases/{base_id}/terms/batch`：items（新增/更新）+ deleted_ids（软删）一次提交，≤5000，重名 409，仅 manual |
| G2 manual 行内批量编辑 | 编辑器重写：添加一行、行内编辑（术语/标准名/英文/分类/同义词/别称 chips）、新增/已修改/已删除标记、恢复、保存全部（名称/描述 + 增改删一次提交） |
| G4 字段级搜索 | 后端 list_terms 支持 search_field（manual 固定字段 / api-db extras 动态列 ilike）；前端搜索字段下拉 |
| G5 api/db 只读 | 编辑器 api/db 只读动态列 + 同步 + 字段配置；隐藏新建/编辑/审核/删除/批量导入；后端词条写操作（创建/更新/审核/删除/批量导入/批量保存）统一拒绝 |
| G6 同步清空重导 | sync 先软删现有词条再导入新词条（源端删除会被清理）；外部词条直接 active（对齐原项目，只读模式无审核入口） |
| 同步/删除 confirm | 主页同步直接执行（列表页已保留）；编辑器“从数据源同步”按钮带加载态；删除为行内标记（保存全部生效） |

## 行为变化说明

1. 外部同步词条不再为 pending，直接 active（原项目行为；api/db 只读无审核入口）；
2. 同步会清空重导：源中已删除的词条会被清理，该术语集下手工补充的词条也会被覆盖；
3. manual 词条保留审核（通过/驳回）作为增强；待审核状态仅用于历史数据或后续流程。
