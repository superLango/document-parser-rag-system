# HansonDOC RAG 测试实施铁律（每阶段强制）

> 本文档为**实施文档**：任何阶段（框架、功能、改造、迁移、重构）开发完成，
> 必须按本流程执行完整测试。所有测试/迁移测试脚本统一存放在本项目
> `qa/` 目录下，禁止散落在 backend/、frontend/、/tmp 等位置。

## 0. 硬性铁律（违反即评审无效）

1. 必须按照【待测模块清单】逐个模块完整测试，**不跳过任何模块、不合并多个模块的测试用例**。
2. 测试分层执行，**五层缺一不可**：
   - L1 单元测试（Unit）
   - L2 集成链路测试（Integration）
   - L3 功能场景测试（Functional / E2E）
   - L4 边界异常测试（Boundary & Exception）
   - L5 安全渗透测试（Security & Penetration）
3. 每一条用例固定六要素格式：**场景编号、前置条件、操作步骤、预期结果、断言校验规则、回归判定标准**，不能简化。
4. 存在以下特征的模块必须补充**并发测试用例**：
   异步、WebSocket、定时器、iframe 沙箱、撤销重做、Token 过期、并发请求。
   （本项目当前涉及：异步 API、Token 过期/刷新、并发请求。）
5. 遇到历史遗留隐患（代码审查中标注存疑的逻辑），必须**单独新增复测用例**。
6. 禁止编造不存在场景；禁止省略失败场景；异常场景禁止只测正常流程。
7. 全部用例完成后必须输出【测试覆盖率统计表】，标注每个模块用例数量与是否全覆盖。
8. **覆盖率低于 95% 视为未完成测试**，必须补全后才能进入下一阶段。
9. 阶段结束时，所有测试脚本、测试报告、覆盖率统计归档到 `qa/` 下。
10. **页面全流程闭环测试（入口闭环铁律）**：凡涉及前端页面的新增/改造/迁移，
    L3 功能场景必须走“真实入口 → 操作 → 数据落库 → 进入内页 → 返回/列表刷新”
    完整闭环，禁止只用直接输入内部路由（goto URL）代替入口验证；
    创建/导入/上传类功能必须断言数据真实落库（UI 展示或 API 查询），
    禁止仅断言 toast/请求发出；失败路径同样必须从真实入口触发。细则见第 6 节。

## 2. 用例编号规则

`L{层}{模块}-{序号}`，例如：

- `L1M3-01`：单元测试·RBAC 角色模型
- `L2M1-02`：集成链路·登录→刷新→访问
- `L3M4-03`：功能场景·新建用户
- `L4M1-04`：边界异常·过期令牌
- `L5M3-05`：安全渗透·越权访问角色接口
- `REG-01`：历史遗留隐患复测

## 3. 用例六要素格式（固定模板）

```
【场景编号】L?M?-??
【所属模块】M?
【前置条件】...
【操作步骤】
1. ...
2. ...
【预期结果】...
【断言校验规则】
- 断言 1：...
- 断言 2：...
【回归判定标准】
```

## 4. 回归判定标准（统一定义）

| 结果 | 判定 |
|------|------|
| 通过 | 所有断言逐条成立；无控制台错误；无横向溢出；无未捕获异常 |
| 失败 | 任一断言不成立，或出现未预期错误/数据不一致/权限绕过 |
| 阻塞 | 环境/依赖不可用，需记录原因并恢复后重跑（不算通过） |

## 5. 覆盖率统计表模板

| 模块 | L1 单测 | L2 集成 | L3 功能 | L4 边界 | L5 安全 | 用例总数 | 是否全覆盖 |
|------|---------|---------|---------|---------|---------|----------|------------|
| M1 认证登录 | n | n | n | n | n | n | 是/否 |
| ... | | | | | | | |
| **合计** | | | | | | | |

覆盖率 = 实际执行的（模块×层）组合 / 计划执行的（模块×层）组合；
单模块覆盖率 = 该模块实际通过用例数 / 计划用例数 ≥ 95% 方为完成。

## 6. 页面全流程闭环测试要求（强制，入口闭环铁律细则）

> 目的：防止出现“功能可用但用户从真实入口进不去/数据没真正落库”的缺陷。
> 适用于所有前端页面功能（新增、改造、迁移、重构），评审时逐条核对。

### 6.1 真实入口闭环（禁止仅直接 URL 验证）

1. 每个页面的 L3 功能用例必须**从用户真实入口进入**：
   - 外部页面：侧栏菜单/工作台卡片 → 目标页面；
   - 知识库内部：知识库卡片 → 内部菜单 → 目标页面；
   - 二级页面（详情/管理/编辑）：从列表卡片/行操作按钮进入，**禁止以直接 goto
     内部路由作为主验证**（直接 goto 仅允许作为调试/回归辅助步骤并显式标注）。
2. 必须验证**返回路径**：内页返回后，列表/上下文状态与操作前一致（如返回后
   新创建卡片可见、删除后目标消失）。
3. 涉及“点击 XX 进入”的交互，必须断言进入后目标内容真实可见（如 h1/表格数据），
   不能只断言 URL 变化。

### 6.2 数据落库闭环（禁止仅断言请求/toast）

1. 创建/导入/上传/同步类功能必须断言**数据真实落库**：
   - UI 层：卡片词条数、列表行、详情字段、状态徽标变化；
   - 或 API 层：调用真实接口查询返回记录。
2. 禁止用 mock 伪造成功态替代真实链路；允许使用测试环境内的**真实服务**
   （本地 HTTP 源、测试库、测试接口），但必须走真实 HTTP 接口与真实数据库。
3. 若个别场景必须 mock（如外部不可达系统），必须**另补一条真实链路用例**，
   并在用例说明中标注 mock 范围。

### 6.3 失败路径同样走真实入口

1. 失败用例（连接失败、创建失败、导入校验失败、权限拒绝）必须从真实入口触发，
   禁止直接调用 API 代替页面操作（API 层失败由 L2/L4/L5 覆盖，两者不能互相替代）。
2. 必须断言失败后的 UI 状态：错误提示可见、数据未错误落库、可重试/可返回。

### 6.4 评审门禁（违反即评审无效）

| 检查项 | 通过标准 |
|--------|----------|
| 每个页面 L3 用例含真实入口步骤 | 是，且无“仅直接 goto 内部路由”的主验证 |
| 创建/导入/上传类用例含数据落库断言 | 是（UI 展示或真实 API 查询） |
| 二级页面用例含返回路径断言 | 是 |
| 失败路径从真实入口触发 | 是 |
| 需要 mock 的用例已标注且另有真实链路用例 | 是 |
