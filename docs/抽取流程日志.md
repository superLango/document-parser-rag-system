## 二、测试中发现并修复的问题

### 问题：后处理脚本日志代码引发 `NameError: name 'json' is not defined`

- **现象**：抽取过程中每个类别的后处理阶段均报错，异常被捕获后返回空记录，导致 41 个类别全部被剔除，`total_records=0`。
- **根因**：`backend/app/services/extraction/rule_engine/script_manager.py` 中新增的日志代码使用了 `json.dumps` 序列化输入记录，但该模块**未导入 `json`**。
- **Traceback 关键片段**：

```
File ".../rule_engine/script_manager.py", line 212, in apply_records
    "input_records": [json.dumps(r, ensure_ascii=False, default=str) for r in records],
                      ^^^^
NameError: name 'json' is not defined. Did you forget to import 'json'
```

- **修复**：在 `script_manager.py` 顶部补充 `import json`。
- **验证**：修复并重启 arq worker 后重新触发测试，新增日志中错误数为 **0**，抽取成功产出 95 条记录、18 个有效类别。

## 四、日志覆盖的关键配置来源

本次日志印证了「配置驱动、无硬编码回退」的架构约束，各阶段关键参数均来自数据库配置解析结果（`ExtractionConfigResolver`），而非代码内置默认值：

- **检索**：`top_k=20`、`per_dim_top_k=30`、五维权重、`context_max_tokens=28000`、重排开关/模型/top_n —— 来自 `global_config.retrieval`
- **LLM**：引擎选择 `BaseExtract`、温度 `0.0`、`top_p/top_k/max_tokens/timeout`、并发（cross=24/within=1）、批处理参数 —— 来自 `global_config.llm.engines.BaseExtract`
- **端点**：`http://localhost:9988/v1`、模型 `Qwem3.6-35B-A3B-FP8` —— 来自资源与配置 `kb.config.extraction`
- **Prompt**：system/user prompt、字段定义 `${field_defs}` —— 来自 `kb_prompt_templates` 类别绑定
- **Schema**：类别字段定义与描述 —— 来自 `schema_templates`
- **脚本**：`精准去重`（post 阶段）—— 来自 `kb_rule_group_items`
