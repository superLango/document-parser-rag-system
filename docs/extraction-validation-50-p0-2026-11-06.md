# 50 份 Markdown 验证报告：P0 方案效果与新问题

> 验证日期：2026-11-06  
> 验证语料：`F:\hanson\hanson_doc_parse\markdown` 中 50 份文档  
> 验证方式：rules-only 离线管线（Mock OCR + Mock Extractor），直接运行 `run_pipeline`，对比修改前（baseline）与 P0 修改后（p0）的 schema 结果  
> 结论：P0 对“取样说明”和部分“取样数量”有效，但 50 份语料暴露出更大的结构性问题——**文档适用性、检验表选择、检验行建模**。P0 不能单独作为最终方案。

## 1. 验证范围与方法

- 从 408 份 markdown 中按关键词（取样数量、化学成分、力学性能、检验项目、牌号、持久、拉伸、冲击、硬度）和表格数排序，去重后选取 50 份。
- 每份文档执行：
  1. `ingest` 解析 markdown 页面；
  2. `MockOcrAdapter` 按页读取；
  3. `MockExtractor` 规则抽取表格；
  4. `project_hanson_schema` 生成产品标准 schema；
  5. 统计 schema 行、取样数量/试验方法/取样说明/标准要求缺失、疑似牌号/温度/单位错误。
- 原始结果：
  - `data/validation-2026-11-06/metrics-baseline.json`
  - `data/validation-2026-11-06/metrics-p0.json`
  - `data/validation-2026-11-06/runs/baseline/`、`runs/p0/`
  - 选样清单：`data/validation-2026-11-06/selected50.json`

## 3. 新方案暴露的新问题

### N1. 文档类型不适用，仍被强行套用标准 schema（最严重）

- 50 份中有 **8 份**没有 inspection 数据：包括 ASME 锅炉压力容器规范汇编、质量保证程序、制造大纲等。
- 两份 ASME 汇编分别产生 **7,084 / 8,087 行** schema，几乎全部取样数量/方法为空；它们不是单份标准，套用“产品标准模板”没有意义。
- 影响：整体指标被严重稀释，用户会看到大量空行；如果直接输出，会误以为抽取失败。

**修复方向**

- 增加文档分类器/适用性检查：识别“单份标准 / 标准汇编 / 质量程序 / 制造大纲 / 采购协议”。
- 只对“单份标准”启用产品标准 schema；汇编类走“按标准拆分后再逐份抽取”；程序/大纲类走其他模块或仅保留标准信息。
- 质量门禁：当文档没有 inspection 表且 schema 行数超过阈值时，标记 `not_applicable`，不输出大量空行。

### N2. 检验表选错：选到“第三方复验/尺寸表”而不是主检验表

典型文档：

- `65c7cfb8…`：inspection 19 条，item 全是“成品紧固件的第三方复验项目及数量”“复验抽样规则”，数量是“表3，C”“表3，C(组)，每组3个试样”，不是主检验表。
- `22b1476b…`：inspection 81 条，item 全是“左侧止口直径”“退刀槽深度”“粗糙度”等尺寸项。
- `564ae4f4…`：inspection 15 条，item 全是“紧固件的抽样数量”，数量 1/2/3，但 schema 只建了 61 条化学成分等行，尺寸/紧固件项目未建行。

**根因**

- 当前 inspection 提取按“表头含检验项目/取样数量”选择，但没有区分表角色；同一文档里“第三方复验表”“尺寸检验表”“主检验表”都可能命中。
- schema projection 只按类别（化学成分/拉伸/尺寸）匹配一条 inspection，无法处理“每个尺寸项一行”的 inspection 表。

### N3. 检验项是“维度行”，不是“类别”，schema 无法承接

- `22b1476b…` 有 81 个尺寸类 inspection 行，schema 只生成 11 条“尺寸”行，且取样数量为空。
- `65c7…` 的第三方复验表有 19 行，schema 没有对应类别。
- 结果：大量检验要求存在于 `inspection_items`，但没有进入 schema。

**修复方向**

- 引入 `RequirementRow`：每个 inspection 行是一条独立要求，带 `category/item/grade/condition/quantity/location/method`。
- 对尺寸/外观/无损等类别，应按 inspection 行逐行生成 schema 行，而不是“类别匹配一条”。
- 对无法归类的 inspection 行，进入“未映射检验项”清单，而不是静默丢弃。

### N4. 数量是表引用/文字，当前解析不了

典型值：

- `表3，C`
- `表3，C(组)，每组3个试样`
- `表3，B`
- `复验数量：1个/批`（可解析）
- `抽样数量（件/组）a：1/2/3`（可解析）

**根因**

- `_sample_count` 只处理数字、`逐`、`~`、`%`、`不少于`；遇到“表3，C”直接返回 None。
- 这类值需要回查被引用表（表 3）才能得到实际数量，当前没有跨表引用解析。

**修复方向**

- 保留 `quantity_raw` + `quantity_ref`（表号/列/行），能解析就解析，不能解析就标记 `needs_lookup`。
- 增加“表引用解析”：在同文档 tablegrid 中找“表3”，按 C/B 列/组取值；解析失败则进入异常清单。
- 不要把“表3，C”当成空值。

### N5. 同名检验项多行，数量和条件不同

- `65c7…` 的“成品紧固件的第三方复验项目及数量”重复 19 次，数量分别是 `1个/批`、`表3，C`、`表3，B` 等。
- `564ae4f4…` 的“紧固件的抽样数量”重复 15 次，数量 1/2/3。
- `GJB 5301` 的“硬度”有两行：一行 `-`，一行 `环形件10%，且不少于3件`。

**根因**

- `_find_inspection` 按 item 名称打分，未保留“条件/级别/组别”维度；同名多行只能选一条。
- 当前 `InspectionItem` 没有“条件/级别/组别”字段，无法区分。

**修复方向**

- inspection 行增加 `condition/level/group/grade` 维度；投影时按维度展开为多行。
- 同名多行时不要“选一条”，而是合并成一个 `RequirementGroup`，保留所有数量与条件。

### N6. 空行/过度投影

- 两份 ASME 汇编 7,084/8,087 行，绝大多数为空。
- 部分文档 schema 行远大于 inspection 行（例如 65c7：204 行 vs 19 inspection）。
- 这会让用户误判“抽取了很多内容”，实际有效字段很少。

**修复方向**

- 增加“有效行”概念：至少有一个非空关键字段（取样数量/标准要求/单位/试验方法）才算有效。
- 输出时区分 `schema_rows` 与 `effective_rows`；质量门禁按有效行计算。
- 对 not_applicable 文档不生成产品标准 schema。

### N7. P0 未覆盖的旧问题仍然存在

- 牌号疑似错误 1,788 行、温度 28 行、单位 99 行，与 baseline 基本一致。
- P0 只修了“持久类合并、同义词、说明、数量解析、文件名牌号”，没有修多级表头/列绑定/热处理温度误绑。
- 这些需要 P1 TableFrame 和列角色校验。

### N8. 试验方法缺失仍然很高

- 42 份标准类中仍有 618/2,689 行无试验方法（23.0%）。
- 原因：inspection 表未选中、方法列未识别、method 映射缺失，与 N2/N3 同源。

### N9. 取样说明仍缺 1,165 行（42 份标准类）

- 从 100% 缺失降到 43.3%，但仍有很多 inspection 的 quantities 为空或为表引用。
- 需要 N4 的表引用解析和 N5 的多行合并。

## 5. 下一步修复方案

### P1-A 文档适用性门禁

- 分类：单份标准 / 标准汇编 / 质量程序 / 制造大纲 / 采购协议。
- 只对“单份标准”运行产品标准 schema；汇编类按标准拆分；程序/大纲类走其他 profile。
- 产出 `applicability` 字段，前端显示“该文档不适用标准拆分”。

### P1-B 检验表选择

- 表角色评分：
  - 主检验表：表头含“检验项目/取样数量/取样部位/试验方法”；
  - 第三方复验表：含“第三方/复验项目/复验数量”；
  - 尺寸表：含“尺寸/公差/直径/粗糙度”；
  - 性能表：含“抗拉强度/伸长率/冲击/硬度”。
- 主检验表优先；第三方/尺寸表只在对应类别（如尺寸）内使用。
- 选表结果写入 `inspection_table_id` 和 `selection_reason`，可审计。

### P1-C 逐行 RequirementRow

- 每条 inspection 行生成一条 `RequirementRow`，保留：
  - `category / item / grade / condition / level / group`
  - `quantity_raw / quantity_value / quantity_ref`
  - `location / method / requirement`
  - `source_table / row / evidence`
- schema 投影从 RequirementRow 展开，不再“类别→一条 inspection”。

### P1-D 表引用数量解析

- 对“表3，C”“表3，C(组)，每组3个试样”解析：
  - 找到表3；
  - 按列/组取值；
  - 解析失败保留 raw + `needs_lookup`，进入异常清单。

### P1-E 同名多行合并

- 按 `(item, condition, level, group)` 聚合；
- 保留所有 quantity 变体；
- 投影时按条件展开。

### P1-F 有效行与质量门禁

- `effective_rows` = 至少一个关键字段非空；
- 空行率超过阈值或 inspection 覆盖率过低时，标记 `low_quality`；
- 大汇编类文档禁止生成产品标准 schema。

### P2 TableFrame

- 多级表头、合并单元格、按级别/类别分列；
- 这是 GJB 5301、GBT 33084、GBT 40303 这类文档的根本修复。

## 6. 建议

1. **P0 可以保留**：它没有引入回归，且把标准类文档的取样说明缺失从 100% 降到 43.3%，部分文档取样数量明显改善。
2. **P0 不足以解决 50 份语料的主要问题**：真正的瓶颈是 N1（文档不适用）、N2（选错检验表）、N3（维度行无法承接）。
3. 下一步优先做 **P1-A + P1-B + P1-C**，再跑同一批 50 份对比；预期比继续加同义词收益更大。
4. 在 P1 完成前，不建议把 50 份指标作为对用户承诺的准确率；当前结果主要反映规则/投影，不包含真实 Qwen 抽取。
