# GB-T1220-2007 抽取问题排查报告（2026-08-17）

> 排查对象：LangExtractPkg 引擎收敛专项测试结果
> `qa/evaluation/results/langpkg_full_features/run.json`，对照 OCR 产物
> `kb-25e7d8ef.../ocr/8b2f746f.../result.md`（69,639 字符 / 31 页）。
> 结论基于只读排查（未重跑抽取）。

## 0. 结果概览

- 41 个类别全部参与（skipped=0），仅 6 个有记录：标准信息 58、室温拉伸 31、布氏硬度 1、
  低倍 12、化学成分 7、塔形 0（1 条被拒）；其余 35 个类别 LLM 返回空数组。
- 所有类别命中分数 0.015~0.036（阈值 0.035），**检索相关性整体极低**。

## 1. 标准信息：object 返回 array 且内容错误

**现象**：期望 `{"标准名称":"不锈钢棒","标准编号":"GB/T 1220-2007"}`，实际返回 58 条
数组，全部是规范性引用文件中的其他标准（GB/T 222、GB/T 223.x…），且 `_evidence` 显示
内容对齐正确（模型没抽错，是"抽错了目标"）。

**根因**：
1. `return_type=object` 未实现：原包输出恒为 `{"extractions":[...]}` 数组，
   `lang_pkg_extractor._parse_result` 始终返回 list，未按 object 收敛为单对象；
2. 检索召回了「2 规范性引用文件」块（fixed_query 含"GBT/国标/企业标准"，且该块被
   BM25 命中），上下文里引用标准列表排在前面，LLM 将其当作"标准信息"抽取；
3. 封面上的「GB/T 1220—2007 不锈钢棒」块未被召回或排在上下文末尾被截断；
4. Prompt（`prompt_content`）未限定"只抽取本文件的标准名称与编号，排除引用文件"。

## 2. 室温拉伸：统一数字代号被识别为牌号

**现象**：`材料牌号:"S21860"`（S21860 是统一数字代号，真实牌号为 14Cr18Ni11Si4AlTi）。

**根因**：
- Schema 无「统一数字代号」字段，表 6/7 的列序为「GB/T 20878中序号 | 统一数字代号 |
  新牌号 | 旧牌号 | …」，LLM 把第二列 S 开头代号归入「材料牌号」；
- 字段描述仅"该检测类型下的牌号"，未指明取"新牌号"列；
- 检测项目术语集只有「材料牌号」可映射，无代号字段可供对齐。

## 3. 布氏硬度：只识别到 1 条

**现象**：仅 `022Cr19Ni5Mo3Si2N ≤290`（表 7 首行），表 8/9/10 的 HBW 列
（183/219/228/170/192/217…）全部缺失。

**根因**（只读检索验证）：
- `布氏硬度` 检索 top10 中前 3 名是**规范性引用文件/前言**（score 0.019~0.035），
  表 7/8/9 排在后面；上下文按命中顺序拼接 + 块数截断（7277 字符≈前 3~4 块），
  真正含硬度数据的表块未进入上下文或只进了一行；
- 项目名称须从术语集匹配「布氏硬度(HBW)」，但上下文无对应列说明，模型只抽取到
  前言/表 7 中明确写"不大于 290"的 1 条。

## 4/5/6. 化学成分试验方法未填充、化学成分不全、各类别丢失大量内容

**现象**：化学成分仅 7 条且全部是 C 元素（表 5 沉淀硬化 4 牌号 + 表 2 双相钢 3 牌号），
表 1/3/4 的 C、Si、Mn… 全部缺失；试验方法字段全空。

**根因**：
- **召回不全**：化学成分 query 召回 10 块，上下文 8950 字符只覆盖表 1-5 的约 4~5 块，
  表 1（奥氏体 ~20 牌号）、表 3（铁素体）、表 4（马氏体 ~19 牌号）大部分行未进上下文；
- **表格切块破坏结构**：单块 3000 字符按句子边界切分，大 HTML 表格（一行 ~20 行数据）
  被拆散，模型在每个 chunk 内只能看到表的一部分行；
- **项目名称只匹配到一个**：化学成分术语集有 60+ 元素 NAME，但记录里项目名称全为
  "C"，模型未按列拆分为多条（Si/Mn/P/S/Ni/Cr… 未输出）；
- **试验方法空**：表 1-5 无方法列，试验方法在表 16/规范性引用文件中；上下文是否覆盖
  表 16 取决于召回，且模型判断"表中无方法"留空，术语集匹配未兜底。

## 7. 有些类别没有抽取到（35 个空）

分两类：
- **文档中确实没有**（高温拉伸/低温拉伸/持久/蠕变/疲劳/淬透性/落锤/缺口拉伸等）：
  返回空数组符合 Prompt"无该类数据返回空"约定，合理；
- **文档中有但未抽到**（热处理制度、晶间腐蚀、弯曲、洛氏/维氏硬度等）：
  - 热处理制度：检索能召回附录 A 块（pages 21-23），但 Schema 字段为
    升温速率/保温时间/冷却介质/出炉温度等，而标准表 A.1-A.5 只有
    退火/淬火/回火温度列，**Schema 与标准内容不匹配**，LLM 匹配不到字段值返回空；
  - 晶间腐蚀：表 12 值多为"协议""不允许有晶间腐蚀裂纹"，模型不认为是明确数据；
  - 布氏/洛氏/维氏硬度：硬度数据嵌在表 7-10 的"硬度"列，检索未把对应块排到上下文
    前面，且项目名称术语集匹配受限。

## 8. 底层共因（影响全部类别）

1. **检索召回质量差**：所有类别命中分 0.015~0.036；query 由类别名 + 30 个检测项目
   NAME + 30 个方法代码拼接（最长 2000 字符），长 query 稀释语义；无 reranker；
   BGE-M3 对中文标准文档匹配分极低；大表被 2000 字符子块拆散，检索只命中少数块。
2. **Schema 字段与标准列结构不对齐**：缺「统一数字代号」字段；热处理制度字段与
   标准温度列不匹配；项目名称依赖术语集精确匹配，多列表只输出 1 列。
3. **return_type=object 未实现**（标准信息）。
4. **Prompt 语义**：标准信息未限定排除引用文件；记录粒度约束要求单值拆分，
   但模型在表格行上只输出一条记录（室温拉伸 31 条=31 牌号×仅 Rp0.2）。

## 9. 修复方向（供后续决策，未实施）

- 检索：缩短 query（类别名 + 少量关键词）、开启 reranker、提高 top_k、按版面块聚合
  大表（整表一个块）；
- Schema：补充统一数字代号字段；热处理制度按标准实际列调整字段；项目名称拆条由
  后处理/脚本兜底而非仅靠 LLM；
- 适配器：实现 return_type=object 收敛；标准信息 prompt 限定"仅本文件标准"；
- 抽取：表格行级抽取（按行拆分记录）或结构化 TSR 前置。
