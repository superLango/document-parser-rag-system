# 检索召回与重排诊断报告（2026-08-17，GB-T1220-2007）

> 诊断脚本：`qa/functional/retrieval_diag.py`；结果：`qa/evaluation/results/retrieval_diag/diag.json`。
> 未触发抽取。目标：定位抽取质量差的根因是"召回候选缺失"还是"排序/重排不足"。

## 1. 方法

- A. 39 个展开类别：hybrid 检索 top15（无重排），统计 query 长度/术语数/命中分数/
  目标内容块（按页面范围推断的表格块）是否进入候选；
- B. 关键 7 类：叠加 bge-reranker-v2-m3 重排，统计目标块排名与耗时；
- C. BGE-M3 余弦：query 与目标块相似度直接验证。

## 3. 结论

1. **两类问题并存**：
   - **候选缺失**（化学成分、布氏硬度）：目标表块未进 RRF top15，reranker 无法解决
     （它只重排已有候选）。余弦 0.6 说明向量"能匹配上"，是被 RRF 截断挤出的；
   - **候选内排序不足**（其余 5 类）：目标块在候选内但排名靠后/被噪声压制，
     reranker 可改善（低倍 1,6→0,2；塔形 3→0；晶间腐蚀 3→1）。
2. **query 长度敏感**：精简后 query 仍过长（16 项/218-242 字符），多术语拼接稀释
   BGE-M3 语义；手工简化 query（3-9 项/30-39 字符）时化学成分表块进 top4-5、
   布氏硬度表块进 top9-13。布氏硬度 5 项 query（含 GB/T231-1984、JIS 旧方法代码）
   比 3 项 query 召回更差——无关方法代码污染 query。
3. **rerank 耗时**：首载 ~15s，之后每类别 1-9s（化学成分 1.5s、室温拉伸 4.7s、
   晶间腐蚀 8.9s）；41 类全量约 2-5 分钟。适合流式"重排完一个类别即抽取"。
4. 室温拉伸抽取退化（31→1 条）由 max_char_buffer=12000 大块导致，与召回无关；
   max_char_buffer=6000 版本因中断未跑完，待验证。

## 4. 修复方向

- **query 压缩**：feature + 精简 NAME 前 2-4 个 + 最新 1 个方法代码（方法标准号改由
  BM25 精确匹配），目标 query 控制在 50 字符内；
- **reranker 保留 + 流式化**：重排完一个类别立即进入该类别抽取，不等全部；
- 抽取侧：max_char_buffer=6000 验证（大块退化问题）。
