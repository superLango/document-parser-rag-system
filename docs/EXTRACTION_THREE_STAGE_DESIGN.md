# 结构化抽取三阶段设计：结构解析 → 程序关联 → 字段补全

> 状态：设计细化（待确认）
> 目标：解决「检测项目/试验方法/取样数量分布在多个块」导致的字段缺失，
> 并正确处理「项目多方法」「尺寸档位不同标准要求不同」等行级/项目级关联。

## 1. 为什么类别级共用不行（真实证据）

GH4169 力学性能表 p6_1（节选）：

| 棒材直径mm | 取样方向 | 试验温度℃ | σb MPa | σ0.2 MPa | δ5 % | ψ % | 硬度HB | 持久 t℃/σ/τh |
|---|---|---|---|---|---|---|---|---|
| 80~125 | 纵向 | 室温 | 1275 | 1035 | 12 | 15 | ≥346 | 650/690/≥25 |
| >125~200 | 横向 | 室温 | 1240 | 1035 | 6 | 8 | ≥346 | 650/690/≥25 |
| >200 | 横向 | 室温 | 1230 | 1020 | 6 | 8 | ≥346 | 650/690/≥25 |

- 标准要求随「尺寸档位×方向×温度」变化 → **行级属性**，不能类别级共用；
- 同一行含多个项目（拉伸+硬度+持久）→ 拆条必须在行级做；
- 试验方法/取样数量在检验项目表（表5）+ 方法条款（4.3.x）→ **另一个块**。

## 2. 整体流程

```
力学性能表(p6_1)            检验项目表(表5) + 方法条款(4.3.x)
      │                              │
      ▼                              ▼
阶段1 结构解析(LLM)            阶段2 程序关联(程序)
  表格 → 行级骨架              项目 → {取样数量, 取样部位, 方法}
      │                              │
      └────────────┬─────────────────┘
                   ▼
         阶段3 字段补全(LLM)
      骨架 + 项目映射 + Schema → 最终记录
```

## 3. 阶段1：结构解析（LLM，纯结构、无领域语义）

**输入**：力学性能表 HTML（p6_1）
**职责**：展开 rowspan/colspan、多级表头，输出干净的「表头展平 + 行数据」。
**不做**：项目语义理解、拆条、字段映射——这些留给阶段3。

**输出**（真实 p6_1 前 2 行）：

```json
{
  "table_id": "p6_1",
  "headers": [
    "棒材直径mm", "取样方向", "试验温度℃",
    "抗拉强度σb(MPa)", "屈服强度σ0.2(MPa)", "断后伸长率δ5(%)", "断面收缩率ψ(%)",
    "室温硬度HB", "持久试验温度t(℃)", "持久应力σ(MPa)", "持久寿命τ(h)", "持久伸长率δ(%)", "持久寿命τ'(h)"
  ],
  "rows": [
    ["80~125", "纵向", "室温", "1275", "1035", "12", "15", "≥346", "650", "690", "≥25", "≥5", ">τ"],
    ["80~125", "纵向", "650", "1000", "860", "12", "15", "≥346", "650", "690", "≥25", "≥5", ">τ"]
  ]
}
```

要点：
- 表头展平（父列名+子列名，单位并入），行数据完整展开（rowspan 前向填充）；
- 输出与表同规模，紧凑，LLM 无歧义；
- **行级属性（直径档位/方向/温度）随行保留**——后续按行生成记录不丢失。

## 4. 阶段2：程序关联（确定性）

**输入**：检验项目表（表5）+ 方法条款正文（4.3.x）
**职责**：解析成「项目 → 元信息」映射。
**为什么程序做**：检验项目表结构规整（项目/数量/部位/章条号），解析是确定性工作；且映射可复用、可审计。

**输出**：

```json
{
  "室温拉伸": {"取样数量": "2", "取样部位": "相当于铸锭头、尾部棒材各1", "方法": "4.3.2"},
  "高温拉伸": {"取样数量": "2", "取样部位": "相当于铸锭头、尾部棒材各1", "方法": "4.3.3"},
  "高温持久": {"取样数量": "2", "取样部位": "相当于铸锭头、尾部棒材各1", "方法": "4.3.4"}
}
```

方法条款正文（4.3.2 等）解析为「章条号 → 具体方法」：
```json
{"4.3.2": "GB/T 228.1-2021 金属材料 拉伸试验 第1部分", "4.3.3": "GB/T 4338 金属材料 高温拉伸试验方法", ...}
```

要点：
- 映射按项目名（术语集归一）建立，**项目多方法 = 数组**（如 `"方法": ["4.3.2", "4.3.2 备注"]`）；
- 若项目表/正文解析不确定，此处可调 LLM（但输出仍是结构化映射）。

## 5. 阶段3：字段补全（LLM 综合生成）

**输入**：
1. 阶段1 的行级骨架（含尺寸档位/方向/温度/各列值）；
2. 阶段2 的项目映射（项目→取样/方法）；
3. Schema（字段定义：材料牌号/项目名称/单位/标准要求/试验方法/取样数量/取样部位/方向/尺寸厚度/试验温度/试样状态/锻件类型…）。

**职责**：跨表语义对应 + 拆条 + 生成最终记录。
- 把骨架的每一列/每一行对应到项目（如：直径80~125、纵向、室温 的 σb 列 → 室温拉伸项目的「抗拉强度」，标准要求 1275 MPa）；
- 从项目映射取方法/取样/部位填到记录；
- 按 Schema 拆条：一行多项目 → 多条记录。

**输出**（骨架第一行拆出的记录示例）：

```json
[
  {"材料牌号": "GH4169", "项目名称": "抗拉强度", "单位": "MPa", "标准要求": "≥1275",
   "尺寸厚度": "80~125", "方向": "纵向", "试验温度": "室温",
   "试验方法": "GB/T 228.1-2021", "取样数量": "2", "取样部位": "相当于铸锭头、尾部棒材各1", "试样状态": "..."},
  {"材料牌号": "GH4169", "项目名称": "屈服强度", "标准要求": "≥1035", "尺寸厚度": "80~125", "方向": "纵向", "试验温度": "室温", "试验方法": "GB/T 228.1-2021", ...},
  {"材料牌号": "GH4169", "项目名称": "持久寿命", "标准要求": "≥25h", "尺寸厚度": "80~125", "方向": "纵向", "试验温度": "650", "试验方法": "4.3.4对应方法", ...}
]
```

## 6. 关键设计点

| 问题 | 解法 |
|---|---|
| 尺寸档位不同标准要求 | 骨架行自带档位/方向/温度，拆条保留 |
| 项目多方法 | 阶段2 映射值为数组；阶段3 按需填 |
| 试验方法/取样跨块 | 阶段2 程序解析并注入阶段3，不靠 LLM 跨块猜 |
| 一行多项目 | 阶段3 按列×Schema 拆条 |
| 项目名归一 | 阶段2/3 用术语集 match_record（已有） |
| 不依赖领域 | 阶段1 纯结构；阶段2 程序解析通用表；阶段3 LLM 综合 |

## 8. 待确认点

1. 阶段1 是否要拆成「纯结构」还是「结构+列名归一」（把 σb → 抗拉强度）？
   建议：阶段1 纯结构（无歧义），归一放阶段3。
2. 阶段2 检验项目表解析用程序正则还是 LLM？建议程序（表结构规整），不确定时 LLM 兜底。
3. 阶段3 是 LLM 生成完整记录，还是程序合并骨架+映射（LLM 只做列→项目映射）？
   建议：LLM 生成（跨表语义对应需要理解）。
