# v3 结构化抽取流程：配置来源与回退说明

> 范围：从「文档向量化 + 五维入库完成」进入抽取逻辑（`extraction_tasks.extract_document_impl`）开始，到抽取结果落盘（`extract_result.json`）为止。
> 目的：逐阶段说明每个配置/参数是从哪里读取的、默认值是多少、是否有回退以及回退到哪、执行了什么逻辑。

---

## 一、整体流程串讲

```
extract_document_impl (arq 任务)
  └─ extraction_pipeline.run(task_id, doc_id, kb_id)
       ├─ ① 解析配置  resolver.resolve(db, kb_id) → cfg
       │     └─ 挂载 LLM 端点  kb_config_loader.load(kb_id) → cfg.endpoint
       ├─ ② Phase 2 类别构建  category_builder.build
       ├─ ③ Phase 3+4 类别并发抽取  _extract_categories
       │     └─ 每类别: retrieval_service.retrieve → extract_with_fallback → script_manager.apply_records
       └─ ④ 结果保存  result_writer.save → {OCR_OUTPUT_DIR}/{task_id}/extract_result.json
```

---

## 二、配置三大来源与回退总原则

| 层级 | 来源 | 说明 |
|---|---|---|
| **cfg**（`ExtractionDomainConfig`） | 数据库 `kb_extraction_config`（全局配置）+ `schema_configs`（Schema 模板类别/字段）+ `kb_prompt_templates`（Prompt 模板）+ `kb_term_bindings`（术语绑定）+ `kb_rules`/`kb_rule_groups`（规则）+ `kb_datasets`（数据集） | 与 `defaults.py` 深合并，`cfg` 是最高优先级 |
| **settings**（`ExtractionSettings`） | `app.core.config.settings` 的 `EXTRACTION_V3_*` 环境变量 | `cfg` 未取到时的次优先级回退 |
| **模块级硬编码默认** | 各文件顶部 `_XXX` 常量 | 兜底默认值，通常与 `defaults.py` 一致 |

**回退总链条**：`cfg`（KB 级配置）→ `settings`（全局环境变量）→ 模块级硬编码默认。

**cfg 解析失败**：`resolver.resolve` 异常时 `pipeline` 仅记日志，置 `cfg=None`，后续阶段全部回退到 `settings`（见 [extraction_pipeline.py](file:///home/hanson/doc_parse_project/backend/app/services/extraction/extraction_pipeline.py#L100-L107)）。

### ④ Phase 4 抽取（extractor_factory / BaseExtract / LangExtract）

**引擎选择**：显式参数 → `cfg.llm.engine` → settings `extraction_engine`（`extract_with_fallback`）。

| 配置项 | 来源（BaseExtract） | 来源（LangExtract） | 默认值 | 回退 |
|---|---|---|---|---|
| 批处理阈值/批字符/重叠 | `cfg.llm_batch().single_threshold/batch_chars/overlap` | — | 8000/6000/500 | → settings |
| 单次截断保护 | `cfg.llm_batch().context_truncate` | — | 32000 | → settings |
| max_tokens | `target.max_tokens` → `cfg.max_output_tokens()` | `target.max_tokens`（**Bug 见 §五**）→ `cfg.max_output_tokens()` | 32768 | → settings |
| temperature | `cfg.engine_temperature()` | 同左 | 0.0 | → settings `llm_temperature` |
| top_p / top_k | `engine_params.top_p/top_k` | — | 0.1 / 20 | → settings |
| enable_thinking | `engine_params.enable_thinking` | 同左 | False | — |
| timeout | `engine_params.timeout` | — | 300 | — |
| format_type / fence_output | — | `engine_params.format_type/fence_output` | JSON / False | — |
| max_examples | — | `engine_params.max_examples` | 3 | → 硬编码 3 |
| passes / context_window_chars / max_char_buffer | — | `engine_params.passes/context_window_chars/max_char_buffer` | 2/28000/40000 | → settings |
| within_category 并发=max_workers | — | `cfg.within_category_concurrency()` | 3 | → settings |
| LLM 端点 base_url/api_key/model | `cfg.endpoint` | `cfg.endpoint` | — | → settings |
| few-shot 示例 | — | 字段 `example` + `max_examples` | — | 无 example → 空 |
| output_schema | — | `target.schema`（Schema 模板字段） | — | 无 schema → None |

**Prompt 渲染**（`config_prompt_renderer.render_category`）：
- 来源：`cfg.prompt_for_category(template_id, category_id)`
- 回退链：类别绑定模板 → 同 Schema 模板的 simple 模板 → `None`
- **无模板时不回退到内置 Prompt**：
  - BaseExtract：`user_prompt` 为空 → **跳过抽取返回 []**（[base_extract_extractor.py](file:///home/hanson/doc_parse_project/backend/app/services/extraction/llm_extract/base_extract_extractor.py#L135-L140)）

**字段定义文本**：`${field_defs}` 占位符，由 `build_field_defs` 生成（字段名/描述/必填标记），可选值注入已移除。

## 六、能否从头串起来？（链路完整性结论）

**能串起来**，符合"配置驱动"设计：`cfg` 由 `resolver` 从数据库 + `defaults.py` 组装，Phase 2/3/4/后处理各阶段均以 `cfg → settings → 硬编码` 三级回退消费配置，无"内置 YAML prompt 回退"（已移除，无模板时跳过或报错提示）。

**但若要落地到某单引擎全流程可用**，需先修复：
1. **#1 LangeExtract `target` Bug**：不修则 LangExtract 引擎完全不可用（全部空结果）。
2. **#2 `script_timeout` 接线**：让配置真正生效。
3. 其余（#3-#6）为可选优化。
