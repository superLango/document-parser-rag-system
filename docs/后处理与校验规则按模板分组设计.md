# 后处理与校验规则：按 Schema 模板分组改造设计

## 背景与目标

现有「后处理与校验规则」是扁平结构（stage 切换 + 作用域三元组），且规则来源为内置规则。
本次改造：

1. **规则来源改为仅脚本**：每种类别下只添加/引用「脚本管理」中的自定义脚本，不再使用内置规则。
2. **按 Schema 模板分组**：一个 Schema 模板对应一个「规则组」，组内按类别展开配置。
3. **完全替换**旧扁平规则列表。
4. 规则间支持**拖拽排序**决定执行顺序。

## 数据模型

### 1. 新表 `kb_rule_groups`（规则组，模板一对一）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID PK | |
| kb_id | UUID | 知识库，RLS 隔离 |
| name | String(100) | 规则组名（可空，默认取 Schema 模板名） |
| schema_template_id | UUID | 关联 Schema 模板（必选） |
| description | String(500) | 描述（可空） |
| created_at / updated_at | datetime | |

约束：`Unique(kb_id, schema_template_id)` —— 一个模板一个规则组。

### 2. 新表 `kb_rule_group_items`（类别下的规则项）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID PK | |
| kb_id | UUID | RLS 隔离 |
| rule_group_id | UUID FK→kb_rule_groups | 所属规则组 |
| category_id | UUID | SchemaConfig 类别节点 id |
| category_name | String(100) | 类别名冗余（运行时按 feature 名匹配） |
| script_id | UUID FK→kb_scripts | 引用的脚本 |
| stage | String(20) | post 后处理 / validation 校验（仅标记归属，不决定先后） |
| sort_order | int | 同类别内执行顺序（跨 stage 统一，拖拽排序） |
| created_at / updated_at | datetime | |

约束：`Unique(rule_group_id, category_id, script_id, stage)` —— 同一类别不重复引用同一脚本（同一脚本可既处理后处理又校验，视为两条）。

## 后端接口（extraction_config.py，前缀 /kbs/{kb_id}/extraction-config）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /rule-groups | 列出规则组（含模板名、类别数） |
| POST | /rule-groups | 新建规则组（name 可空默认模板名、schema_template_id 必选、description） |
| GET | /rule-groups/{id} | 详情：模板下所有类别 + 每类别的规则项（含脚本名/描述/阶段） |
| PUT | /rule-groups/{id}/items | 批量保存某类别的规则项（[{category_id, script_id, stage, sort_order}]） |
| DELETE | /rule-groups/{id} | 删除规则组（级联删规则项） |

废弃旧的 `/rules`、`/validation` 接口（前端不再调用）。

## 前端（ExtractionConfig.vue「后处理与校验规则」Tab 重写）

1. 顶部「新建规则组」按钮 → 弹框（名称可空默认模板名、Schema 模板 Select 必选、描述输入）。
2. 规则组列表卡片，可展开。
3. 规则组展开 → 显示该模板下所有类别（默认收起）。
4. 类别展开 → **单栏**列表，后处理与校验规则混排在同一张表中
   （不分栏），每行显示脚本名 + 描述 + 阶段徽标（后处理/校验）。
5. 每类别的「添加」→ 弹框内**先选择阶段（后处理/校验）**，随后脚本下拉
   **仅列出该阶段**（post ¥ 抽取后处理目录 / validation ¥ 校验目录）的脚本，
   选择后保存加入该单栏列表。
6. 规则项支持**跨阶段统一拖拽排序**（后处理与校验可交叉排列），持久化 sort_order。

## 执行引擎改造

现状：`extraction_pipeline` 调用 `script_manager.apply_records(db, kb_id, "post", records, feature, doc_id, target)`，
按 `folder` 加载所有激活脚本。

改造：运行时按「类别」关联脚本。

- `apply_records` 改为查询 `kb_rule_group_items`：先按 kb_id 找到规则组，再按 `category_name == feature` 匹配类别，
  加载该类别该 stage 的启用脚本，按 `sort_order` 顺序执行。
- 未配置任何规则组/类别脚本时，回退为「无脚本，原样保留」，行为不回归（脚本走完即默认透传）。
- 保留 `kb_tools` 工具句柄注入（脚本内可调用 embed / semantic_search / match_record / get_term_records）。

> 说明：feature 名（sm_feature.NAME）与 SchemaConfig 类别名（name）在抽取配置中一致，
> 故用 `category_name == feature` 匹配；category_name 在保存规则项时冗余写入。

## 迁移

新增 Alembic 迁移 `01x_rule_groups.py`，创建 `kb_rule_groups`、`kb_rule_group_items` 两表并加 RLS 策略。

## 验收

- 新建规则组并绑定模板 → 界面显示规则组，展开见所有类别。
- 在某类别下添加后处理/校验脚本 → 该类别对应栏显示脚本名/描述/阶段徽标。
- 拖拽排序 → 保存后 refresh 顺序保持。
- 抽取流程按类别执行对应脚本，未配置类别透传。
