## 1. 阶段定位

M1/M1.5/M1.6 解决“表里的值怎么抽准”；M1.7 解决两个前置问题：

1. **这个标准里到底有哪些检验项目？**（Item Inventory）
2. **该看的地方是否都看了？**（OutlineGraph + CoveragePlan + 覆盖审计）

不先确定项目清单，抽取就没有目标；不证明覆盖，就无法回答“有没有漏”。

不做：业务系统名称/编码对齐（M1.8）；平台前端集成（M1.9）。

## 6. 项目发现规则

### 6.1 四路证据

| 来源 | 规则 | 产出 |
|---|---|---|
| 检验项目表 | 表型 `inspection_rules`，逐行读“检验项目”列 | item_raw + 方法/取样/条款 |
| 性能表 | 列绑定后的 `item_family` + `facets` | item + properties |
| 条款/方法 | “应进行 X 检验”“X 按 GB/T…”“检验项目包括…”“见表 X” | item + method/clause |
| 被引用标准 | 缺口触发 `CrossStandardTask` | 补 item 或 method |

排除：前言、目次、规范性引用文件、资料性附录（除非明确要求）。

### 6.2 合并/去重

- 项目名归一（空格、全半角、别名）；
- 同 family + facets + method 视为同一项目；
- 同一项目多个证据合并 evidence；
- 冲突：同名不同方法/不同 facets → `ambiguous`，不自动合并。

### 6.3 细分

- 拉伸：温度（室温/高温/低温）；
- 冲击：冲击类型（夏比/仪器化）+ 温度；
- 硬度：标尺（布氏/洛氏/维氏）；
- 持久/蠕变：温度、应力、时间/速率；
- 项目身份 = family + facets，不是单一名称。

### 6.4 覆盖审计

- 每个 measure 列必须映射到某个 item + property；
- 每条“应进行 X 检验”的句子必须映射到 item；
- 未映射 → `unknown_candidates`；
- 文档画像为分类标准/技术协议时，缺失字段标 `not_applicable`，不进入缺口。
