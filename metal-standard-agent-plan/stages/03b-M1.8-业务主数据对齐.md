### 1.2 三类术语集接入说明（2026-10-27）

业务系统确认采用 hansonDoc_RAG 的三套术语集：**项目大类、检测项目、试验方法**。接入方式：

1. 从 hansonDoc_RAG Postgres `term_bases`/`terms` 只读导出（KB `25e7d8ef-...`）到
   `data/business_terms/raw/hanson_terms_export.json`；
2. `tools/import_hanson_terms.py` 转换为 `BusinessDictionary` 快照：
   - 项目大类：`type="category"`，family/facets 由 `classify_item` 推导；
   - 检测项目：`type="item"`，`category_code/category_name` 指向项目大类（`feature` 字段），
     括号/尾符号（`抗拉强度(Rm)` → `Rm`）、`ITEM_ALIAS`、英文名进入别名；
   - 试验方法：`type="method"`，`standard_no = METHOD_CODE`；
3. 版本号取原始导出文件的 SHA256 前 8 位（`hanson-58583e54`），保证可追溯。

对齐层级：

```text
ItemInventoryEntry（项目组：item_raw/family/facets/properties）
  ├─ match_item      -> 项目大类（category）
  ├─ match_property  -> 检测项目（item），按大类优先
  └─ match_method_cell -> 试验方法（method）
```

已知限制（业务数据侧，已在报告中量化）：

- 7 个 `feature` 不在 39 个项目大类内（断裂韧性、疲劳、紧固件、夹杂、点蚀当量、艾氏冲击、钢铁及合金），
  其检测项目保留 `category_name` 但不挂 `category_code`（21 条）；
- 同名/同符号检测项目 7 组（如 `C`、`Fe`、`Rp0.2` 多名），系统返回 `ambiguous` 并单列“业务数据冲突”，不静默合并；
- 试验方法词典以化学分析为主，机械/金相/无损方法覆盖不足，未命中的标准进入 `new_terms`（方法 36 条）。

## 6. 匹配规则

### 6.1 项目大类（项目组）

1. 归一化：空格、全半角、上下标、罗马数字/阿拉伯数字、同义词；
2. 精确：业务名称完全一致；
3. 别名：业务维护的同义词（如 `低倍` ← `低倍组织`、`高倍组织` ← `显微组织`）；
4. 包含：业务名/别名包含于抽取名（或反向）；短名（<3 字）要求相似度 ≥0.6，避免 `弯曲` 命中 `弯曲度`；
5. facets：室温/高温、夏比/仪器化、洛氏/维氏/布氏冲突则不合并；业务大类未细分该维度时按大类归并并记录原因；
6. 语义：bge-m3 余弦，阈值默认 0.90（可配，可注入）；
7. 仍不命中 → `new_category`。

### 6.2 检测项目（组内属性）

1. 属性代码（`Rm`、`Rp0.2`、`HBW`、`C`）→ 名称/别名/符号；
2. 符号优先级：括号符号（`抗拉强度(Rm)`）> 尾符号（`断后伸长率A/%`）> 业务别名；
3. 元素符号（`C/Si/Mn/...`）固定归化学成分，不受分组影响；
4. 大类内优先；大类内没有时全局兜底（硬度表常混排 HBW/HRC/HV），并记录检测项目所属大类；
5. 同名/同符号多条 → `ambiguous`（业务数据冲突），不静默取一条；
6. 未命中 → `new_item`。

### 6.3 试验方法

1. 标准号优先：`GB/T 228.1` 归一后匹配；
2. 同标准多版本：文档给出年代号且命中 → 精确；未给年代号 → 取最新版并记录原因；
3. 名称+标准号双键；不能只按名称模糊；
4. 方法别名（旧标准号、缩写）；
5. 未命中 → `new_method`；内部条款引用（`8.1`、`B.2.5`、`附录C`）不建立方法。

### 6.4 阈值与误合并

- 精确/别名优先，语义仅补充；
- 语义命中必须满足：分数 ≥ 阈值 + facets 不冲突；
- 室温/高温、洛氏/维氏/布氏、夏比/仪器化冲突 → 不合并；
- 误合并率目标 <1%，超过即停用自动合并。

## 7. 新项目/新方法流程

```text
抽取 → 未命中
  → new_terms.json（pending）
  → 平台复核页（M1.9）
  → 业务确认（接受/改名/映射到已有/拒绝）
  → 写入业务词典或术语集（pending→active）
  → 下次自动命中
```

规则：

- 不自动写业务系统；
- 可写本地术语集 `pending`，审核后 `active`；
- 保留原始 raw、facets、证据、标准号；
- 同一 raw 多次出现合并为一条候选，累计频次。

## 8. Prompt 白名单注入

借鉴 hansonDoc_RAG `prompt_renderer` 的占位符机制：

- `${whitelist_section}`：业务已有项目/方法列表；
- `${query_terms}`：业务别名/同义词；
- `${item_facets}`：温度/冲击类型/硬度标尺约束。

原则：

- Prompt 只降低匹配压力，**最终以确定性匹配为准**；
- 白名单过长时按 family 裁剪，避免稀释；
- 未命中不得由 Prompt 强行补全。

### 8.1 在线接入契约

业务系统可采用两种返回形态，二选一：

1. 单字典端点：`GET {base}/business-dictionary`，返回
   `{"version":"...","entries":[{"business_code","business_name","type","family","facets","aliases","standard_no","status"}]}`；
2. 分端点：`GET {base}/items` 与 `GET {base}/methods`，返回列表或
   `{"version":"...","data":[...]}`。

鉴权与字段：

- 鉴权：`Authorization: Bearer <token>`（可用 `BUSINESS_AUTH_HEADER`/`BUSINESS_AUTH_PREFIX` 覆盖）；
- 字段别名：`item_code/project_code/code`、`item_name/project_name/detection_item_name`、
  `method_code/method_name/test_method_name`、`std_no/standard`、`status/enabled`；
- 状态：`active/enabled/1/启用` → active；`inactive/0/停用` → inactive；`pending/待确认` → pending；
- 版本：响应体 `version` 或响应头 `X-Dictionary-Version`。

环境变量：

```text
BUSINESS_API_BASE_URL=http://<business-host>
BUSINESS_API_KEY=<token>
BUSINESS_DICTIONARY_PATH=/business-dictionary   # 可选，单端点模式
BUSINESS_ITEMS_PATH=/items
BUSINESS_METHODS_PATH=/methods
BUSINESS_AUTH_HEADER=Authorization
BUSINESS_AUTH_PREFIX=Bearer 
```

验收命令：

```powershell
# 三类术语集快照（hansonDoc_RAG）
python tools/import_hanson_terms.py
python tools/business_smoke.py --snapshot configs/business_dictionary.hanson.json --runs runs/m1.5_qwen --out eval/business/hanson

# 单测基线词典
python tools/business_smoke.py --snapshot configs/business_dictionary.json --runs runs/m1.5_qwen --out eval/business/snapshot

# 在线业务系统（端点恢复后）
python tools/business_smoke.py --base-url $env:BUSINESS_API_BASE_URL --api-key $env:BUSINESS_API_KEY
```

|---|---|---|
| 业务名称不规范 | 同义/缩写多 | 术语集 + 人工确认 |
| 语义误匹配 | 高分但不同项目 | family/facets 约束 |
| 字典版本漂移 | 业务改主数据 | 版本快照 + 结果记录 |
| 新项堆积 | 长尾多 | 聚类 + 批量确认 |
| Prompt 泄漏 | 白名单过长 | 按 family 裁剪 |
