## 1. 阶段定位

标准文档版式多样。如果每份文档都重新写抽取脚本/提示词，成本不可控；如果只用一个通用提示词，复杂表会崩。

M2.5 用“配方”解决：

- 通用配方覆盖高频版式；
- 结构签名检索，先命中已有配方；
- 低置信/未知文档进入探索队列；
- 新配方经影子运行、人工审批后晋升；
- 生产只跑 active 配方，不跑未验证脚本。

## 2. 入口条件

- G2 通过；
- 20 份文档有稳定抽取结果；
- 表画像/表头签名可计算；
- 三队列/注册表存储可用；
- 领域专家可审批配方。

## 3. 范围

### 3.1 做

- 配方 schema；
- 表型/版式签名；
- 结构检索 top-k；
- 参数绑定；
- Router（production/explore/human）；
- 三条队列；
- L0–L5 晋升；
- 影子运行；
- 回滚/弃用；
- 离线 authoring 沙箱；
- 冷启动指标。

### 3.2 不做

- 生产环境执行模型生成的任意代码；
- 未审批配方自动发布；
- 全自动配方生成；
- 多租户配额（M5）。

## 4. 架构

```text
TableGrid + DocumentProfile
        │
        ▼
SignatureBuilder → signature
        │
        ▼
RecipeRetriever → top-k candidates + confidence
        │
        ├─ high confidence → production queue → active recipe
        ├─ low confidence  → exploration queue → T1/T2/T3
        └─ risky/ambiguous → human queue
        │
        ▼
RecipeRunner → 抽取结果
        │
        ▼
Shadow → Promote(L4) / Reject / Rollback
```

## 5. 配方模型

### 5.1 配方 schema（示例）

```json
{
  "recipe_id": "mech_grade_rows_v3",
  "version": "3.1.0",
  "status": "active",
  "applies_to": {
    "doc_type": ["gb_t", "gjb", "enterprise"],
    "table_profile": "mechanical_properties",
    "orientation": "grade_rows",
    "header_signature": ["牌号", "热处理状态", "取样方向", "Rm", "Rp0.2", "A"]
  },
  "bindings": {
    "grade_column": {"match": ["牌号", "钢级", "级别"]},
    "condition_columns": {"match": ["热处理", "状态", "方向", "温度"]},
    "property_columns": {"match": ["Rm", "Rp0.2", "A", "Z", "HB"]},
    "unit_patterns": ["MPa", "%", "HBW"]
  },
  "rules": {
    "comparator_from_header": true,

    "require_evidence": true

  "extractor": {
    "mode": "two_stage_qwen",

    "max_rows": 200,

  "provenance": {
```

## 6. 工作包与任务

### 6.1 M2.5.1 配方模型

| ID | 任务 | 实现 | 验收 |
|---|---|---|---|
| M2.5.1-01 | 配方 schema | JSON Schema 校验 | 声明式、可版本化 |
| M2.5.1-02 | 结构签名 | 表头 token、列数、表型、方向 | 同族稳定 |

| M2.5.1-04 | 配方测试框架 | 合同测试 + 金样例 | 3–10 例/配方 |

**签名设计**：

```text
signature = {
  profile, orientation,
  n_cols,
  header_tokens: [规范化表头 token],
  block_count,
  has_multi_header,
  unit_set
}
```

- 表头 token 先去空格/别名/脚注；
- 签名不包含具体数值；
- 同族文档签名相似度可用 Jaccard/余弦。

### 6.2 M2.5.2 检索与路由

| ID | 任务 | 实现 | 验收 |

| 条件 | 路由 |

| 无命中/低置信 | explore |

| 预算耗尽 | human |

**M2.5.3 实现**：`recipes/lifecycle.py` 内置上述闸门（L2/L3/L4 的 evidence 字段与阈值见 §0.2）；`recipes/shadow.py` 产出 L3 证据；`tools/recipe_lifecycle.py` 提供 promote/rollback/deprecate；三队列实现见 `queues/store.py`（三条独立 JSONL lane，互不阻塞）。

## 8. 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| Recipe Hit Rate | 命中 active 配方文档 / 总文档 | ≥80% |
| Novelty Rate | 无命中/新签名 / 总表 | <20% |
| Conversion Rate | 探索→active / 探索批次 | 持续 > 新格式出现率 |

### 9.1 失败分支

## 10. 风险

| 风险 | 触发 | 应对 |
|---|---|---|
| 配方过拟合 | 同族换文档崩 | 聚类代表 + 影子 + 签名约束 |
| 签名不稳 | OCR 表头变化 | 别名/容错/多签名 |
| 配方爆炸 | 每份文档一个 | 参数化 + 合并 |
| 未审批配方上线 | 流程漏洞 | 注册表状态机 + 权限 |
| authoring 沙箱越权 | 代码执行 | 只读源文 + 无网络 + 人工审 |
