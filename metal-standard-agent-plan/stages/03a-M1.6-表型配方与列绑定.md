## 1. 阶段定位

M1 解决“表里的值能抽”；M1.5 解决“引用与困难表”；M1.6 解决“**格式差异不再靠改代码**”。

核心判断：

- 结构归一化（rowspan/colspan、跨页、转置）是引擎能力，做一次；
- 表型/列语义差异是**配置**，用配方和列绑定表达；
- 只有出现引擎无法表达的新结构，才改代码。

本阶段不做：全文条款覆盖、业务主数据对齐、平台改造；这些在 M1.7/M1.8/M1.9。

## 4. 架构

```text
TableGrid
  ├─ signature 提取（profile/列数/表头 token/方向/块数/跨页）
  ├─ Recipe Router
  │    ├─ 精确命中 → 绑定配方
  │    ├─ 近似命中 → candidate + 人工确认
  │    └─ 未知     → 探索模式（LLM 草稿 + 金样例 + 审批）
  ├─ Column Binding
  │    ├─ 表头树切组
  │    ├─ 组名关键词 → item family
  │    ├─ 叶列属性码/单位 → property/role
  │    └─ 条件列/行值 → facets
  └─ 输出 column_bindings / item_groups / conflicts / ambiguous
```

## 6. 列绑定算法

### 6.1 判定顺序

1. 显式组名/条款名（室温拉伸、夏比冲击、洛氏硬度）；
2. 试验方法标准（GB/T 228.1、GB/T 4338、GB/T 229、GB/T 230.1、GB/T 4340.1、GB/T 231.1）；
3. 条件列/行值（温度、方向、状态）；
4. 属性码/单位（Rm、KU2、HRC、HV、HBW）；
5. 都不满足 → `ambiguous`。

### 6.2 组切分

- 按 `header_paths` 的父节点，连续列构成组；
- 最深且可识别的项目节点作为 `item_family`；
- 若只有“力学性能”大类，降级到叶列属性签名；
- 多块表重复组按 `(family, property, facets)` 合并，不按行展开。

### 6.3 列角色

| 角色 | 判定 |
|---|---|
| `row_key` | 牌号/级别/统一数字代号 |
| `condition` | 规格、方向、温度、状态、热处理 |
| `measure` | Rm/ReL/A/Z/KU2/HBW/τ 等 |
| `method` | 试验方法/标准号 |
| `remark` | 备注、表注 |

### 6.4 细分与 facets

- 拉伸：温度（室温/高温/低温/具体值）；
- 冲击：冲击类型（夏比/仪器化）+ 温度；
- 硬度：标尺（布氏/洛氏/维氏）；
- 持久/蠕变：温度、应力、时间/速率。

细分是“family + facets”，不是扁平枚举；`低温夏比冲击` = family=impact + impact_type=夏比 + temperature=低温。

### 6.5 冲突/歧义

- 组名与方法冲突 → `mapping_conflict`；
- 组名缺失且属性歧义 → `ambiguous`；
- 未映射列 → `unmapped_columns`；
- 不允许根据数值反推项目。
