## 1. 阶段定位

M0 不是“做功能”，而是把后续所有开发所需的**判断基准**建立起来：

- Schema v0 能被业务/领域签字；
- 黄金集能作为评测真值；
- 人工/商用基线能回答“值不值得做”；
- 环境能真实启动 GLM-OCR / Qwen；
- CI 能拦住回归。

M0 不通过，不启动 M1 的真实模型链路；但允许 M1 的解析/接口工作用 mock 并行准备。

## 4. 工作包与执行步骤

### 4.1 M0.1 治理与签字

#### M0.1-01 范围确认

1. 技术负责人整理首期范围：4 类文档、5 类表、schema 必填字段；
2. 业务确认“不做全条款/全表格”；
3. 领域确认技术协议/采购协议/分类标准的处理方式；
4. 产出会议纪要与范围说明，双方签字。

**验收**：范围说明含 In Scope / Out of Scope / 文档类型 / 表类型 / 首期三份打样文档。

#### M0.1-02 验收阈值

1. 逐条确认 G0–G5 指标（见 v2 第 13 章）；
2. 明确哪些指标是阻断项，哪些是观察项；
3. 明确指标分母（字段/记录/文档）；
4. 业务 + QA 签字。

**验收**：阈值表带签字页；所有指标有定义与计算公式。

#### M0.1-03 决策日志

1. 建立 `decision-log.md`；
2. 每条记录包含：日期、决策、理由、影响、负责人、关联任务；
3. 变更 Schema/阈值/模型版本必须引用日志条目。

#### M0.1-04 首期文档

1. 确认三份：GB/T 1591-2018、GB/T 40303-2021、Q-Du 302-2015；
2. 确认各自覆盖点与已知难点；

#### M0.1-05 “完整”的定义

2. 全规范性条款/全表格留到 M1.7 之后；
3. 写入范围说明，避免验收争议。

### 4.2 M0.2 黄金集收口

#### M0.2-01 数字原生缺口

当前 6 原生 + 1 混合 + 13 扫描。两条路径：

- 路径 A：补 2 份数字原生 PDF（推荐），满足 8+12；
- 路径 B：业务书面接受 6+1+13，并在评测中分“原生/扫描”报告。

**验收**：决策日志 + manifest 更新。

#### M0.2-02 冻结 manifest

1. 确认 20 份清单；
2. 校验 `md_path`、`pdf_path` 存在；
3. 校验 doc_id 唯一；
4. 冻结 `goldset/v0/manifest.json`。

```powershell
python -m metal_doc_agent.cli gold validate --manifest goldset\v0\manifest.json --strict
```

**注意**：`--strict` 会报告数字原生缺口；缺口未关闭前视为 G0 未通过。

#### M0.2-03 双人复核

1. 标注员 A/B 各拿一份独立副本；
2. 按 `(table_id, record_key, property)` 与 `(clause_id, field)` 比对；
3. 输出 diff：值、comparator、unit、evidence、status；
4. 争议项进入仲裁清单。

**A/B 检查重点**：

- `min/max/range` 是否按“要求方向”；
- 区间端点是否完整；
- 单位是否来自表头；
- 证据 quote 是否可检索；
- `scope=partial` 是否写清未标范围；
- `ambiguous` 是否只用于真歧义。

#### M0.2-04 仲裁

1. 领域专家逐条裁决；
2. 记录依据（源文/页图/标准条款）；
3. 更新标注与 `reviewers`；
4. 争议不决的项标 `ambiguous`，不进入评分。

#### M0.2-05 升级状态

1. `draft → reviewed → verified`；
2. `verified` 必须有两名 reviewer；
3. 重新跑 `gold validate` 与 `eval`。

#### M0.2-06 GJB 2057A ambiguous

1. 对照 PDF 页图确认“3.4”是否为“3个”；
2. 确认后更新 quantities；
3. 无法确认则保留 ambiguous，并在 `note` 写明。

#### M0.2-07 GH4169 表3 力学表

1. 对照页图确认行列错位原因；
2. 判断是否进入 M1-S3 困难表；
3. 记录到 `hard_tables.md` 初始清单。

#### M0.2-08 一致性统计

输出：


## 7. 风险与应对
