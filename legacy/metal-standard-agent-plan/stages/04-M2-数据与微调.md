4. guided JSON + 两阶段抽取；
5. held-out 评测与回归。

不做：全量重训 base model、在线学习、自动标注上线。

## 4. 数据架构

```text
goldset v1（人工真值）
   │
   ├─ train.jsonl        （按文档切分）
   ├─ dev.jsonl
   └─ heldout.jsonl
   │
   ├─ teacher.jsonl      （教师输出，对齐金标）
   ├─ perturb.jsonl      （OCR 扰动/别名/空格）
   └─ ref_train.jsonl    （引用约束样本）
        │
        ▼
LoRA 训练 → adapter
        │
        ▼
guided JSON + 两阶段抽取 → eval/m2.md
```

### 4.1 切分规则

- 按**文档**切分，不按表/行切分；
- 同一文档的表格、条款、引用不得跨 train/heldout；
- 同族文档（如 GB/T 3191 1998/2010）尽量整族放在同一侧；
- heldout 至少覆盖 4 种文档类型、3 种表型；
- 切分清单写入 `splits.json`。

## 11. 引擎 SFT prompt 切换改造（2026-10-29，S1–S5 已实施，默认仍为 native）

### 11.1 目标与现状

目标：让引擎抽取阶段复用 SFT 两阶段 prompt（阶段 1 表头映射、阶段 2 逐行记录），使 `adapter-v1` 的能力真正进入管线。0.6 的 A/B 已经证明，在引擎自有 prompt 下 adapter 近似退化为 base（field F1 0.744 vs 0.7555）。

现状差距：

| 项 | 引擎现状 | SFT 训练分布 |
|---|---|---|
| 表头 | `extraction/qwen.py` 单阶段 prompt，带 `allowed_properties` / `profile` / `caption` | 仅 `header_paths + sample_rows`，输出 `columns` |
| 行 | 与表头同一次调用 + 规则优先补缺口；条件矩阵走 `matrix.py` | 独立 `row_record`，输出 `grade/condition/properties` |
| 输出 | engine `Record`/`ExtractedValue`，属性名走 canonicalization | 金标命名（含自定义键） |
| 矩阵 | `merge_matrix_output` 整表替换或并入 | 无对应任务 |

### 11.2 设计原则

1. **默认关闭**：`METAL_DOC_EXTRACTOR_PROMPT=sft_m2` 开启，默认 `native` 行为不变。
2. **提示单一来源**：新增 `extraction/sft_prompts.py`，文本与 `tools/prepare_sft.py` 一字不差，并加单测比对，防止训练/推理漂移。
3. **规则优先不变**：规则已识别的列不被 SFT 覆盖，只补缺口（沿用 M2.1 修复后的列优先逻辑，避免 Q-Du 串列复发）。
4. **失败回退**：SFT 输出非法 JSON 或 `properties` 为空时，同表回退 native 一次，计数 `sft_fallback`。
5. **不接管矩阵**：条件矩阵（多列同属性不同条件）继续走 `matrix.py`。

### 11.3 改造点

| 模块 | 变更 |
|---|---|
| `settings.py` | 新增 `extractor_prompt_style`（env `METAL_DOC_EXTRACTOR_PROMPT`，默认 `native`）、`sft_max_tokens`（默认 512） |
| `extraction/sft_prompts.py`（新） | SYSTEM、`header_mapping` / `row_record` 指令；单测与 `prepare_sft.py` 逐字一致 |
| `extraction/qwen.py` | 表头分支 sft_m2：只用 `header_paths + sample_rows`，把 `columns` 映射为 `ColumnBinding`；新增逐行 `extract_row_sft`，输入 `header_paths + mapping + row`，输出转 `Record`/`ExtractedValue` |
| `extraction/matrix.py` | 不变；新增 `is_conditional_matrix(table)` 前置判断，命中直接走 native |
| `pipeline.py` | 阶段 2 前过滤表头行与跨分页重复块；SFT 记录缺证据时按 cell 定位补 `Evidence` |
| 观测 | `trace.json` 记录 `prompt_style`、`sft_calls`、`sft_fallback`、`rows_dropped` |

### 11.4 SFT → engine 映射规则

- `role=grade` → grade 列；`condition` → condition 列；`property` → property 列（属性名保留金标写法，后续走既有 canonicalization）
- `row_record.properties.<key>.raw` → `ExtractedValue(raw, comparator, unit)`；comparator 缺失时按现有规范化推断
- `grade` 为空的行丢弃，计入 `rows_dropped`
- 证据：`raw` 在 row cell 内定位 → `Evidence(cell=...)`，维持 evidence_rate 口径

### 11.5 评测与验收

- 步骤：5 份 heldout 文档跑 `native + base(9989)` 与 `sft_m2 + adapter(9990)`，指标口径同 0.6
- 门槛：field F1 ≥ 0.7555（不低于基线）、header 类错误 ≤ 73、record / coverage / evidence 不降、幻觉率 0
- 不达标则保持默认 native，结论回写本文档

### 11.6 风险

| 风险 | 应对 |
|---|---|
| 逐行调用放大延迟（长表约 30s/行） | 仅普通行表启用；按 `qwen_concurrency` 并发；长表分块 |
| 映射丢失信息 | 单测覆盖 4 类表；保留 native 结果做 diff |
| 提示漂移 | 与 `prepare_sft.py` 文本一致性单测 |
| 过滤误删 | 只删与 header 文本全等或与上一数据行全等的行 |
