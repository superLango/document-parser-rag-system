## 1. 这套文档是什么

`development-plan-v3.md` 回答“做什么、什么时候可以进入下一阶段”；本目录回答“每个阶段具体怎么开发、怎么验收、失败怎么回退”。

每个阶段文档统一采用以下结构：

```text
1. 阶段定位与目标
2. 当前状态与入口条件
3. 范围（做 / 不做）
4. 架构与模块设计
5. 数据契约与接口
6. 工作包与任务（含实现步骤、交付物、验收）
7. 测试与评测
8. 阶段门与失败分支
9. 风险与依赖
10. 交付物与交接
```

## 3. 推荐阅读顺序

1. 先读 `../development-plan-v3.md` 第 0–3 章，理解三平面、迁移/改造/审计策略、新增里程碑；
2. M1.5 收尾后，按 **M1.6 → M1.7 → M1.8 → M1.9a → M1.9** 顺序推进；
3. M1.6 与 M1.7 可部分并行：列绑定先行，项目清单可先用规则版；
4. M1.8 必须等 M1.7 的 ItemInventory 稳定；
5. **M1.9a 先做前端功能取舍、工程骨架与 hansonDoc_RAG 代码审计，不先写业务代码**；
6. M1.9 在 M1.9a 通过后启动：前端先按清单改造，后端再按前端最终功能完善；迁移代码先审计，不用代码删除；
7. M2 之前必须完成 G1.9；
8. M2.5 之前必须有 G2；M3 之前必须有 G2.5；M4 之前必须有 G3；M5 之前必须有 G4。

## 6. 变更控制

- 阶段文档不独立改里程碑目标与阈值；阈值变更先改 `development-plan-v3.md`；
- 每个阶段文档顶部记录版本、日期、对应计划版本；
- 任务状态以项目管理工具为准，文档只描述“怎么做”和“怎么验”；
- 阶段门签字后，文档进入只读归档；下一阶段文档可引用，不修改历史。
