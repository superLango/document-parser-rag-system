## 1. 阶段定位

即使 STP 达到 80%，仍有 20% 文档需要人看。M4 的目标不是“去掉人”，而是让人只花时间在**真正需要判断**的地方：

- 机器给出证据和置信度；
- 人点一下就能定位到页/表/单元格；
- accept/edit/reject 留下可训练的事件；
- 批次审计发现 silent error；
- 高风险字段强制人工。

## 2. 入口条件

- G3 通过；
- result/evidence/audit/trace 格式稳定；
- 人工队列可用；
- RBAC 需求明确。

## 3. 范围

### 3.1 做

- 复核工作台；
- PDF 高亮 + JSON diff；
- 字段 accept/edit/reject；
- 批次复核；
- 修正事件回流；
- 审计报告；
- RBAC/审计日志；
- 主动学习采样；
- silent error 审计。

### 3.2 不做

- 实时协作；
- 移动端；
- 复杂审批流（先单级）；
- 自动发布（仍受闸门控制）。

## 4. 复核流程

```text
任务完成
  → 置信度/风险分
      ├─ 低风险 → 自动发布（受 gate 限制）
      ├─ 中风险 → 批量复核
      └─ 高风险 → 单文档复核
  → 复核人看 PDF + JSON + 证据
      ├─ accept
      ├─ edit（保留原值/新值/理由）
      └─ reject（转探索/人工重做）
  → 事件写入 feedback.jsonl
  → 审计报告
```

## 5. 工作台设计

### 5.1 页面布局

```text
┌─────────────────────────────────────────────┐
│ 文档信息 | 状态 | 置信度 | 提交/拒绝          │
├───────────────┬─────────────────────────────┤
│ PDF 页图       │ JSON 树 / 记录表             │
│ 证据高亮       │ 字段值 + comparator + unit   │
│ 页码导航       │ 证据 quote / 页/表/行列      │
├───────────────┴─────────────────────────────┤
│ 问题列表：L0/L1/L2/L3.5 + missing/ambiguous │
└─────────────────────────────────────────────┘
```

### 5.2 交互

- 点击字段 → 跳到对应页/表/单元格并高亮；
- 点击证据 → 显示 quote 与上下文；
- 修改值 → 记录原值、新值、理由、操作人；
- 批量接受低风险字段；
- 拒绝 → 选择原因（OCR/表头/语义/引用/其他）。

## 6. 数据模型

### 6.1 ReviewEvent

```json
{
  "event_id": "rev-...",
  "job_id": "...",
  "doc_id": "...",
  "field_path": "records[0].properties.Rm",
  "action": "accept|edit|reject",
  "old_value": {"value": 430, "comparator": "min", "unit": "MPa"},
  "new_value": null,
  "reason": "表头为不小于，单位 MPa",
  "reviewer": "user-...",
  "created_at": "..."
}
```

### 6.2 Feedback 数据集

- 只收 `edit/reject` 且带理由的事件；
- 保留原始 OCR/TableGrid 指针；
- 进入训练/回归前需领域复核；
- 不与 heldout 文档混用。

## 8. 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 复核时间下降 | 相对人工基线 | ≥50% |
| 发布证据率 | 发布文档有证据 | 100% |
| silent error | 无证据/错值但未标记 | 0/50 |
| 修正正确率 | 抽检正确 / 修正 | ≥95% |
| 一次通过率 | 无修改直接发布 | ≥80% |
| 高风险拦截 | 高风险字段人工覆盖 | 100% |

## 9. G4 验收

- [x] 复核工作台可用（字段复核 tab + API；E2E 真实 Chromium 走查：字段复核 → 定位 → 接受 → 退出，`e2e/test_main_flow.py`）；
- [x] 证据高亮/定位准确（字段行「定位」深链到 `/viewer?page=&evidence=`；bbox → 引用文本 → 表格块回退高亮；E2E 验证可跳转并返回）；
- [x] accept/edit/reject 可追溯（field_review_events + audit_logs）；
- [x] 修正回流可用（feedback.jsonl，仅收带理由的 edit/reject）；
- [ ] 复核时间下降 ≥50%（无人工基线，未测；E2E 只证明流程可走通）；
- [x] 发布 100% 有证据（52 份语料 silent error 0，证据率 1.0）；
- [x] 50 份审计 silent error=0（实测 **52 份 / 0 条**，`eval/m4-52.json`）；
- [x] RBAC/审计日志可用（KB 成员 + scope + audit_logs）；
- [ ] 修正抽检正确率（哈希抽样 + 标注接口 + 指标已就绪；无真实人工事件/标注，accuracy 未测）。

> G4 结论（2026-10-30）：工作台、字段深链、50+ 份 silent 审计（52/52）、高风险闸门与反馈链路均通过；**复核时间下降**与**修正正确率**依赖真实人工事件，G4 仍不通过（不是代码问题）。

### 9.1 失败分支

| 条件 | 动作 |
|---|---|
| 复核时间下降 <30% | 重估 UI 交互/采样策略 |
| silent error >0 | 停自动发布；扩大审计 |
| 修正回流污染 | 隔离反馈集，领域复核 |
| 高风险漏拦 | 调整风险规则/阈值 |

## 10. 风险

| 风险 | 触发 | 应对 |
|---|---|---|
| UI 交互低效 | 复核慢 | 批量/快捷键/默认接受 |
| 证据定位错 | 改错字段 | bbox/行列强校验 |
| 反馈污染 | 错误修正入训练 | 领域复核 + 隔离 |
| 权限过宽 | 误操作 | RBAC + 审计 |
| 自动发布越界 | silent error | 闸门 + 抽样 |
