## 1. 文档目的

本文档用于固化 Hanson 标准拆分平台重构的项目需求、范围、功能与非功能要求，以及 Q1–Q8 确认事项。所有开发、测试、部署、验收工作以本文档和《架构重构方案》为依据；两者冲突时，以《架构重构方案》为准，并提交决策记录修订。

## 2. 项目背景与目标

在 `new_app/` 中绿地重建标准拆分平台，解决旧系统单体化、双解析路径、沙箱隔离不足、配方不可版本化、Qwen 无智能体运行时、审核与修复耦合等问题。

目标：

1. 只保留标准拆分一条核心业务线。
2. 微服务架构：网关、编排、OCR、Agent、沙箱、配方注册、审核。
3. 配方/模板不可变、可版本化、可沙箱执行、可晋升/回滚/丢弃。
4. Qwen Agent Runtime 支持大窗口、上下文压缩、长任务分段、断点续跑。
5. 全链路可观测、可调试、可回溯。
6. 移除权限、计费、租户、工作区、用户、模块、集成、分享等非核心逻辑。

## 3. 范围

### 3.1 本期范围

| 类别 | 范围 |
|---|---|
| 后端 | 七服务、文档/运行/阶段/事件、反馈/修复/晋升、配方注册、审核 |
| 前端 | 文档库、标准拆分列表、解析详情、审核、反馈、验证、时间线、版本、预览、词典、运行、配方版本 |
| 算法 | OCR/表格结构、矩阵抽取、条款抽取、Schema 投影、审核规则 |
| 模型 | Qwen Agent Runtime、Router/Review/Repair/Triage Agent |
| 沙箱 | 容器隔离、版本挂载、产物校验、资源限制 |
| 部署 | 本地 WSL 验证 + K8s 设计；Canonical 生产方案按 K8s |
| 数据 | 仅导入业务词典；不默认导入旧文档/运行/产物 |

### 3.2 本期不做

- 登录、认证、用户、角色、RBAC、API Key。
- 租户、工作区、成员、邀请、配额、计费、账单。
- 知识库、模块管理、集成任务、分享链接。
- 订单、证书、外包等非标准拆分业务线。
- 配方可视化编辑器、模板设计器。
- 旧前端逐页迁移、旧 API 兼容层。
- 旧代码直接 import 或原地改造。

## 4. 业务主链路

```text
文件上传
  → OCR 解析（页图 / Markdown / 版面 / 表格结构）
  → 模型判断匹配配方/模板
  → 沙箱执行配方/模板代码完成解析
  → 模型审核文档内容与解析结果
  → 发现问题：配方修复 → 沙箱重跑 → 再审核（有界循环）
  → 结构化结果展示
  → 人工审核提交问题反馈
  → 模型全链路处理：根因分析 → 配方兼容性修改 → 沙箱定向重解析验证
  → 用户验证
      → 通过：自动晋升代码版本，后续沙箱统一使用最新稳定版
      → 不通过：丢弃本次修复，稳定版不变
```

## 5. 功能需求

| 编号 | 需求 | 说明 | 验收要点 |
|---|---|---|---|
| FR-001 | 文档上传 | 支持 `.md`/`.pdf`，全局文档库，无知识库 | 上传成功、重复上传幂等 |
| FR-002 | OCR/表格结构 | OCR、页图、版面、TableGrid | 产物完整、可复现 |
| FR-003 | 配方/模板匹配 | 确定性 matcher + RouterAgent | 返回 recipe/template/confidence/reasons |
| FR-004 | 沙箱解析 | 按 digest 挂载配方/引擎，隔离执行 | 无网络、只读、资源受限、产物校验 |
| FR-005 | 审核 | 规则 + ReviewAgent，输出 Finding | 目标可定位、证据可追溯 |
| FR-006 | 结构化结果 | 类别/记录/字段/证据 | 页面可读、可导出、可反馈 |
| FR-007 | 人工反馈 | 针对记录/字段提交问题 | 去重、状态流转、消息记录 |
| FR-008 | 根因与修复 | Triage + Repair，生成候选 | 根因有证据、修复范围明确 |
| FR-009 | 验证与晋升 | 定向重解析 + 回归 + 用户验证 | approve 原子晋升；reject 丢弃 |
| FR-010 | 时间线/回放 | 阶段、耗时、产物、模型摘要 | 可定位失败阶段 |
| FR-011 | 业务词典 | 分类/项目/方法查询 | 与解析结果匹配 |
| FR-012 | 配方版本 | stable/candidate 版本、回滚 | 版本不可变、指针可回滚 |
| FR-013 | 运行列表 | 运行状态、耗时、失败码 | 可筛选、可进入详情 |

## 6. 非功能需求与确认事项

### 6.1 NFR-001：K8s 环境与验证方式（Q1）

| 项 | 要求 |
|---|---|
| 代码层面验证 | 使用当前本地电脑的 **WSL 环境**完成 K8s 安装、配置与功能测试 |
| K8s 发行版 | WSL 内可选 k3s/kind/minikube；M0 阶段 PoC 后固定一种，记录到决策记录 |
| 生产环境 | 仍按 K8s 方案设计；生产集群未就绪前，以 WSL 验证结果作为代码验收依据 |
| 资源配置 | M0/M4 阶段按 WSL 可用资源（CPU/内存/磁盘）制定最小资源清单；生产资源清单另行确认 |
| 环境隔离 | WSL 验证环境与模型服务器分离；不在模型服务器上运行业务服务 |

### 6.2 NFR-002：模型操作与访问（Q1）

| 项 | 要求 |
|---|---|
| 模型操作位置 | 所有模型相关操作（部署、启停、参数调整、压测、日志查看）必须在**模型服务器**上执行 |
| 模型访问地址 | 共**三个地址**：旧代码已记录的两个地址 + 新增 `192.168.1.35`（第三地址） |
| 自动切换 | 任一地址**连续 10 秒无法连接**时，自动切换至下一个可用地址；三地址全部不可用时返回稳定错误码 |
| 切换顺序 | 默认按配置顺序轮询；当前地址故障时依次尝试下一地址；主地址恢复后按配置回切 |
| 防抖 | 切换后设置冷却窗口；单次失败不切换；避免频繁抖动 |
| 切换实现 | 在 agent-service / ocr-service 的模型网关中实现健康探测、熔断、切换、回切；记录切换事件 |
| Qwen 版本 | **固定使用 Qwen 35B 版本** |
| 其他模型版本 | GLM、Layout 等版本配置**参考旧代码实现**，不擅自升级 |
| 配置管理 | 地址、模型名、版本、超时、探测间隔通过配置注入，不写死 |

### 6.3 NFR-003：Qwen 上下文窗口与并发（Q2）

| 项 | 要求 |
|---|---|
| 窗口候选 | 32K / 64K / 128K |
| 选型场景 | 并发数为 **4**，并与 GLM、Layout 等其他模型共同运行 |
| 选型目标 | 在性能、内存占用、稳定性之间选择最优窗口 |
| 选型方法 | M5 阶段基准测试：吞吐、p95 延迟、显存/内存、失败率、截断率 |
| 默认值 | 未完成基准前默认 64K，可配置 |
| 看门狗 | 测试过程中监控模型服务器剩余内存；达到预设阈值时**主动终止测试进程**，避免设备死机 |
| 阈值 | 可配置；需在 M5 基准前根据模型服务器总内存确定，并记录到决策记录 |
| 告警 | 触发看门狗时记录内存、进程、模型、窗口、并发、时间 |

### 6.4 NFR-004：沙箱运行时选型（Q3）

| 项 | 要求 |
|---|---|
| 候选 | containerd（runc）、containerd + gVisor、Kata Containers |
| 评估维度 | 技术特性、资源开销、安全性、与现有架构兼容性、运维复杂度 |
| 评估方法 | M4 阶段 PoC + 评分矩阵；最终选型记录到决策记录 |
| 硬性要求 | 默认无网络、只读 rootfs、非 root、cap drop、seccomp、CPU/内存/PID/时长限制 |
| 兼容性 | 兼容 K8s、可独立部署、可独立扩缩容 |
| 资源开销 | 相对 runc 的额外开销需可量化；不得超过可接受阈值（M4 PoC 确定） |
| 决策 | 当前不预先锁定最终运行时；M4 K4.1 完成评估后确认 |

### 6.5 NFR-005：数据导入策略（Q4）

| 项 | 要求 |
|---|---|
| 默认策略 | **暂不执行全量旧数据导入**（文档、运行记录、产物等） |
| 允许导入 | 仅可考虑导入**业务词典数据** |
| 效果对比 | 重构完成后，将新系统解析效果与旧数据进行对比验证 |
| 达标处理 | 若新系统解析效果达标，**不导入其余旧数据，全部数据重新生成** |
| 未达标处理 | 若效果未达预期，再反馈确认具体导入范围，不预先导入 |
| 旧数据状态 | 旧系统/旧数据保留只读，作为对比基线；不做双写 |
| 数据迁移脚本 | 仅建设词典导入与对比脚本；全量导入脚本按条件后置 |

### 6.6 NFR-006：前端视觉基线（Q5）

- 前端视觉设计**完全沿用现有产品风格规范**。
- 颜色、字体、间距、组件形态、交互反馈、页面布局均以现有产品为基线。
- 允许复制现有 UI 组件到 `new_app/web` 后重写，但不得引入新的视觉语言。
- 必须做视觉回归：核心页面与现有产品保持一致的设计语言。

### 6.7 NFR-007：对象存储（Q6）

| 环境 | 方案 |
|---|---|
| 本地开发 | **MinIO** |
| 本地测试 | **MinIO** |
| 生产 | 按部署环境选择 S3 兼容对象存储；接口保持兼容 |
| 约束 | 代码不得绑定 MinIO 专有 API；使用 S3 兼容接口 |

### 6.8 NFR-008：API 前缀（Q7）

- 所有公开 API 保留 **`/v1`** 前缀。
- 内部 API 使用 `/internal` 前缀。
- 不新增 `/v2`，除非未来发生破坏性变更并单独决策。

### 6.9 NFR-009：人力约束（Q8）

- 当前项目负责人力 **1 人**。
- 所有角色由 1 人兼任；模型服务器操作、业务确认等外部支持单独协调。
- 里程碑无法按多角色并行推进，实际执行按串行顺序推进。
- 开发计划中的时间基线按多角色假设编制；M0 启动时由项目负责人按 1 人排期重新基线，并更新计划文档。
- 单人执行时必须优先保证：契约、测试、文档、可回滚；不得跳过验收门禁。

### 6.10 NFR-010：可观测

- 每个阶段记录 `trace_id/run_id/stage/status/duration/input_refs/output_refs/versions/metrics`。
- 支持 run 时间线、产物清单、事件流、Agent 会话轨迹。
- 指标：运行成功率、阶段耗时、OCR 质量、沙箱失败、审核问题、反馈量、晋升次数、token、上下文压缩/溢出。

### 6.11 NFR-011：安全

- 沙箱默认无网络、只读、非 root、资源受限。
- 网关唯一公网入口；内部服务 NetworkPolicy/mTLS。
- 密钥只注入需要的服务。
- 无用户/租户系统，减少攻击面。
- 模型访问地址与密钥不写入前端。

### 6.12 NFR-012：性能

- 性能指标在新架构下重新基线，不直接沿用旧系统数值。
- 发布前 p95 不劣化于新基线；沙箱/OCR/Agent 分别设定目标。
- 大结果表 1000 行可滚动不卡死。
- 模型窗口/并发调整必须同时评估内存与稳定性。

## 7. 数据与迁移需求

### 7.1 默认数据策略

```text
旧系统数据（文档/运行/产物/反馈）
  → 不默认导入
  → 保留只读，作为效果对比基线

业务词典
  → 可导入新系统
  → 需校验条目数/编码/别名

重构完成后
  → 新系统解析效果 vs 旧数据
  → 达标：不导入旧数据，全部重新生成
  → 未达标：反馈确认具体导入范围
```

### 7.2 对比验收

| 项 | 要求 |
|---|---|
| 对比样本 | 由业务确认的代表性文档 |
| 对比指标 | Record/Field/Value F1、证据、覆盖、silent、延迟 |
| 达标线 | 不低于旧基线，具体阈值由业务/架构在 M8 前确认 |
| 未达标 | 输出差异报告，提交业务确认导入范围 |
| 数据安全 | 旧数据只读；词典导入脚本可重入、可回滚；全量导入仅在 Q4 决策后执行 |

| 类别 | 验收 |

| 数据 | 仅词典导入；效果对比报告；未达标有反馈 |
| 前端 | 视觉沿用现有风格；核心页面 E2E |
| 质量 | 契约、单测、集成、E2E、安全扫描通过 |

## 10. 假设与约束

1. WSL 环境具备安装 K8s 与 MinIO 的资源；不足时使用远程 Linux 验证，但方案不变。
2. 模型服务器可提供三种访问地址（含 `192.168.1.35`）；切换逻辑由业务服务实现，不依赖人工。
3. Qwen 35B 固定；其他模型版本参考旧代码，升级需单独决策。
4. 并发 4 是 Q2 的测试场景，不代表生产固定并发；生产并发另行压测。
5. 旧数据仅作对比基线，不保证运行时兼容。
6. 单人执行，时间基线需在 M0 重新排期。
7. 前端视觉沿用现有产品，不等待新设计稿。
