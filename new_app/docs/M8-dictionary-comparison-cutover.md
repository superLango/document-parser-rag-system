## 1. 里程碑目标

按 Q4 决策完成“词典导入 + 新旧效果对比 + 性能 + 切换 + 归档”：

- **仅导入业务词典**，不默认导入旧文档/运行/产物。
- 重构后对比新系统解析效果与旧数据。
- 若效果达标：不导入旧数据，全部在新系统重新生成。
- 若效果未达标：输出差异报告，反馈确认具体导入范围。
- 性能压测：API、编排、OCR、沙箱、Agent。
- 灰度切换、回滚演练、旧系统归档。

## 2. 范围与不做

### 2.1 范围

| 项 | 内容 |
|---|---|
| 词典映射 | 旧业务词典 → 新词典表/文件 |
| 词典导入 | 可重入、断点续跑、失败清单 |
| 词典对账 | 条目数、编码、别名、状态 |
| 效果对比 | 新系统 vs 旧数据的解析指标 |
| 导入决策 | 达标→不导入；未达标→确认导入范围 |
| 性能 | 压测 API/编排/OCR/沙箱/Agent |
| 灰度 | 试点文档 → 试点用户 → 全量 |
| 切换 | Ingress/DNS 切换 |
| 回滚 | 切回旧系统 |
| 归档 | 旧代码只读/归档；旧数据只读保留 |

### 2.2 不做

- 不做旧 API 兼容层。
- 不做旧数据库双写。
- 不默认导入旧文档/运行/产物/反馈。
- 不预先建设全量导入脚本；仅在效果未达标且确认范围后建设。
- 不做权限/租户迁移（本期无这些模型）。
- 不做模型训练。

## 6. 数据映射（Q4：仅词典）

### 6.1 业务词典

| 旧字段 | 新字段 | 说明 |
|---|---|---|
| `entry.type` | `dictionary.type` | category/item/method |
| `entry.business_code` | `dictionary.business_code` | 业务编码 |
| `entry.business_name` | `dictionary.business_name` | 业务名称 |
| `entry.aliases` | `dictionary.aliases` | 别名列表 |
| `entry.status` | `dictionary.status` | active/inactive |
| `entry.source` | `dictionary.source` | 来源快照 |

规则：

- 编码唯一；重复编码进入人工清单。
- 别名去重；冲突保留原编码并标记。
- 导入脚本可重入、可断点续跑。
- 导入前后做条目数/编码/别名对账。

### 6.2 旧文档/运行/产物（默认不导入）

- 默认不导入，仅只读保留作为效果对比基线。
- 若 M8-06 决策为“效果未达标且确认导入范围”，再补充以下映射：
  - `documents` → 新 `documents`（丢弃 `kb_id`）。
  - `jobs` → 新 `runs` + `run_stages`。
  - `result.json`/`records`/`evidence` → 新 `artifacts`。
  - 旧反馈 → 新 `feedback`。
- 全量导入脚本仅在决策后建设，且必须可重入、可对账、可回滚。

## 7. 对账与效果对比

### 7.1 词典对账

| 项 | 对账方式 | 门槛 |
|---|---|---|
| 条目数 | 源/目标 count | 100% 一致或差异有清单 |
| 编码 | 编码集合对比 | 100% 一致或差异有清单 |
| 别名 | 抽样/全量对比 | 差异有清单 |
| 状态 | active/inactive 对比 | 差异有清单 |

### 7.2 新旧效果对比

| 指标 | 说明 |
|---|---|
| Record/Field/Value F1 | 新系统 vs 旧数据 |
| 证据命中率 | 证据可定位比例 |
| Coverage | 文档类型覆盖 |
| Silent 错误 | 不应增加 |
| 延迟 | p95 |
| 结论 | 达标 / 未达标 + 差异清单 |

- 对比样本由业务确认；至少覆盖主要文档类型。
- 达标线在 M8-05 前由项目负责人 + 业务确认，写入决策记录 D-008。
- 未达标：输出差异报告，进入 M8-06 决策，不直接全量导入。

## 8. 性能与灰度

### 8.1 压测场景

| 场景 | 指标 |
|---|---|
| 上传 | p95、错误率 |
| 创建 run | p95、排队 |
| 编排 | 阶段耗时、失败率 |
| OCR | 页/秒、p95 |
| 沙箱 | 并发、p95、OOM |
| Agent | token/任务、p95 |
| 结果查询 | p95、大结果 |

### 8.2 灰度步骤

```text
1. 试点文档（10 份）→ 新旧结果对比
2. 试点用户（内部）→ 新入口
3. 10% 流量 → 观察 24h
4. 50% 流量 → 观察 24h
5. 100% 流量 → 旧系统只读
6. 一个发布周期后归档旧系统
```

### 8.3 回滚触发条件

- 错误率 >5%（5 分钟）。
- p95 超过基线 2×。
- 数据不一致/丢失。
- 阻断性缺陷。

| 旧系统归档误删 | 快照/tag；只读保留周期 |
| 单人执行延期 | 串行推进；优先保证词典/对比/切换主线 |

## 12. 出口准则与回滚

**出口准则**

- 词典对账通过。
- 新旧效果对比报告完成，数据导入决策已签字。
- 压测达标。
- 灰度/切换/回滚演练通过。
- 旧系统归档完成。
- 项目负责人 + 业务（按需）验收。

**回滚**

- Ingress/DNS 切回旧系统。
- 新系统数据保留，不删除。
- 旧系统代码未修改，可直接服务。
