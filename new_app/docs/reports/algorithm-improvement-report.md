## 一、测试规模与方法

| 项目 | 说明 |
|---|---|
| 语料 | `汉唐标准` 六类共 185 份 PDF（国家标准 54 / 国军标 32 / 美国标准 82 / 行业标准 11 / 企业标准 3 / 国际标准 3），另有 4 份 >25MB 跳过 |

| 核对方法 | 逐条记录回读 PDF 原文，校验等级、数值、单位是否能在记录所在页找到 |

## 三、问题定位与修复

### 3.1 解析算法（parser_core 1.0.13 → 1.0.15）

| # | 问题 | 影响样本 | 修复 |
|---|---|---|---|
| 1 | 转置配方误命中“牌号成行、元素成列”的表，把元素符号当牌号 | GBT 3077-2015（82 条 `grade='~'`）、GBT 3280-2015（82 条全 `~`） | 增加转置布局判定：首列多为元素符号且表头无元素列才按转置解析 |
| 2 | 牌号列未被使用，成行表只能落占位符 `~` | 同上 | 非转置分支优先用牌号列作 grade；无绑定标量时按行成记录并保留真实牌号 |
| 3 | 单位抽取把 `/` 后的元素符号当单位（如 `化学成分(质量分数)/% / C` 取到 `C`） | GBT 3077、GBT 3280、GBT 14976 | `_extract_unit` 按 `/` 分段找第一个像单位的片段，并排除元素符号 |
| 4 | 诊断缺少表头，无法区分“缺列”与“缺绑定” | 全部配方类问题 | `MEASURE_COLUMN_MISSING.detail` 增加 `headers` 与 `bound_measures` |
| 5 | 牌号列纵向合并时续行为空，记录被丢弃或落 `~` | GBT 14976、多条件力学表 | 续行沿用上一行牌号，新增 `MERGED_GRADE_FILLED` 诊断 |
| 6 | 脚注长段落被当成数据行；“equal to 75mm” 被抽成 Rm=75；错列产生超范围值 | ASTM F67（8 条假牌号）、GBT 1591 等 | `_is_footnote_row` 识别长段落/`a.` 条目；`_prose_cell` 拒绝 >80 字符单元格；新增 `VALUE_OUT_OF_RANGE` 守卫（ksi、kgf/mm² 先换算） |

### 3.2 流水线

| # | 问题 | 修复 |
|---|---|---|
| 5 | 大页数扫描件 OCR 超时即整份 run 失败 | 编排捕获 `httpx.TimeoutException` 后用 `backend=pdf` 重试一次原生文本抽取（[workflow.py](../services/orchestration/workflow.py)） |
| 6 | 反馈补丁只替换目标分表，同一配方其它分表版本不一致 → `SANDBOX_RECIPE_CONFLICT` | `_override_assignments` 改为同一 recipe 的全部分表一起升级 |
| 7 | 模型服务器内存被 35B 挤占，OCR 推理变慢数倍 | 35B 改 `gpu-mem 0.28 / max-num-seqs 2 / max-model-len 24576`，统一内存可用回到 33GB |
| 8 | 同一牌号+条件下跨页/跨表碎片记录重复 | 沙箱 runner 增加 `_merge_fragments`：字段互补则合并，字段重叠保持独立（`FRAGMENT_RECORDS_MERGED`） |
| 9 | 配方 row_key / conditions 别名不足，`ROW_KEY_NOT_FOUND` 4490 次 | 7 个配方扩展别名（名称/材料/材质/合金牌号/统一数字代号/新牌号/原牌号/designation/material 等） |

- 无回归，三份主力样本记录/字段与 1.0.15 持平或微增

#### 1.0.22 新增：英文元素名映射

`_element_symbol` 原先只有“前两个字母恰好等于元素符号”的启发式：Silicon / Titanium / Aluminum 可命中，Iron / Manganese / Chromium / Zinc / Zirconium 全部失配，Copper 还被错误映射为 Co（钴）。AMS 转置成分表因此判不出元素，整表 0 记录。1.0.22 增加 60+ 英文元素名到符号的映射，并跳过 `--` / `remainder` 等非数值单元。单表验证 AMS4108G 的 T2 产出 2 条正确记录（Min：Cu/Mg/Zn/Zr；Max：Si/Fe/Cu/Mn/Mg/Cr/Zn/Ti/Zr）。

## 五、残留问题

| 问题 | 规模 | 性质 |
|---|---|---|
| 扫描件无法文本回查 | 80/185 份 | 度量限制，非解析错误；需要视觉核对或人工抽检 |
| 数值超范围 | 455（50 份样本，基线 542） | 多数为真实上下限/范围值；错列造成的假值已被 `VALUE_OUT_OF_RANGE` 拦截 |
| 等级/数值命中率受文本层影响 | GBT 1591、GBT 3623 | 全角文本层与跨列牌号导致字面匹配失败；解析结果正确，核对脚本待补归一化 |
| 重复主键 | 368（50 份样本，基线 502） | 多条件表（室温/高温、方向）的 condition_key 仍需配方 bindings.conditions 覆盖 |
| 大文档并发 OCR 失败 | 2/50 | 两份大文档同时 OCR 时模型端瞬时不可用（1662s）；需限制大文档并发或增加退避重试 |
| 无牌号元素表 | AMS4108G / 4911S / 4943M、GB 24627 | 1.0.22 已支持英文元素名；GB 24627 属另一种“元素为列”版面，仍 0 记录 |
| Agent 自动修复通过率 | 0/13 | 需用表头/诊断证据约束补丁生成，或保持“建议 + 人工确认”流程 |

> 基线指 parser 1.0.13 的全量批跑（185 份）；标注“50 份样本”的指标来自 4.4 的分层抽样验证，与全量口径不可直接相加。全量 185 份的 1.0.22 复跑因单份大文档耗时过长未执行完，最终以 50 份代表性样本结论为准。

## 六、结论

1. **流水线健壮性达标**：OCR 超时不再导致整份失败，10 份原 FAILED 文档 0 失败、8 份恢复结构化。
2. **解析算法在目标缺陷上达标**：转置误判、牌号列缺失、单位误取三类问题修复后，占位牌号清零，字段量提升 10%–8.6 倍。
3. **解析器已资产化**：`parser_core` 1.0.22 已晋升 stable，后续算法改动可通过资产发布热更新，无需重建镜像。
4. **四轮改进均无回归**：合并单元格、脚注行、超范围守卫、无主表过滤、碎片合并、配方别名扩展上线后，样本记录/字段持平或提升；GBT 14976 占位牌号 11 → 0，重复键 31 → 2；ASME SB265 字段恢复至 129；英文元素名映射（1.0.22）在 AMS4108G 单表验证正确（Cu/Fe/Mn 等不再失配或误判），生产重跑未完成。
5. **Agent 修复能力部分达标**：诊断与草案生成可用，闭环验证仍为 0；现阶段应作为“人工修复的加速器”，而不是自动修复器。
6. **50 份代表性样本最终验证达标**：STRUCTURED_READY 39 → **40**，FAILED 7 → **2**；真实错误类指标全面下降——OCR/归一化 168 → **10**、限值格式 72 → **1**、超范围值 542 → **455**、重复主键 502 → **368**。等级/数值命中率的表观下降已定位为全角文本层与跨列牌号的核对口径问题（剔除影响文档后数值命中率持平 89.0%）。剩余 2 份 FAILED 均为大文档并发的模型端瞬时不可用，单独重跑可恢复。
